# AI-FDE Engine 部署方案（MVP v0.1.0）

> 文档版本：v0.1.0 | 日期：2026-09-06

## 0. 开箱即用快速开始（真实组件版）

> 默认配置已切换为真实组件：DeepSeek LLM + Docling文档解析 + Qdrant向量库 + DeepEval评测 + Aider代码生成 + Mem0记忆。
> Docker Compose一键启动所有依赖服务，无需手动安装任何Python包。

### 0.1 前置要求
- Docker 24+ 和 Docker Compose v2
- 至少8GB内存（推荐16GB）、50GB磁盘空间
- DeepSeek API Key（[申请地址](https://platform.deepseek.com/)）或 Qwen API Key

### 0.2 三步部署

```bash
# 第1步：克隆项目并进入部署目录
cd ai-fde-engine/deploy

# 第2步：配置环境变量（只需填API Key，其他默认即可）
cp .env.example .env
# 编辑 .env，填入你的 API Key：
#   DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxx
#   （可选）QWEN_API_KEY=sk-xxxxxxxxxxxxxxxx

# 第3步：一键启动（自动构建镜像+启动6个服务）
docker-compose up -d --build
```

### 0.3 验证部署

```bash
# 查看所有服务状态
docker-compose ps

# 查看应用日志
docker-compose logs -f ai-fde-app

# 健康检查（应返回 {"status":"healthy"}）
curl http://localhost:8000/api/v1/health

# 打开API文档
# 浏览器访问 http://localhost:8000/docs
```

### 0.4 默认真实组件清单

| 模块 | 默认实现 | 依赖服务 | 降级策略 |
|------|----------|----------|----------|
| LLM大模型 | DeepSeek V4 Pro/Flash | 外部API | API Key缺失时提示配置 |
| 文档解析 | Docling 2.0 | 无（CPU内置） | 未安装时降级mock |
| 向量知识库 | Qdrant v1.18 + bge-m3 | docker-compose qdrant服务 | 服务未启动时降级mock |
| 评测引擎 | DeepEval | 无（LLM-as-Judge） | 未安装时降级mock |
| 代码生成 | Aider | 无（git内置） | 未安装时降级mock |
| 记忆系统 | Mem0 + 时序知识图谱 | 无（JSON持久化） | 未安装时降级hybrid |

### 0.5 常用运维命令

```bash
# 停止所有服务
docker-compose down

# 重启应用（配置修改后）
docker-compose restart ai-fde-app

# 重新构建镜像（代码更新后）
docker-compose up -d --build ai-fde-app

# 查看资源占用
docker stats

# 数据备份
bash backup.sh
```

### 0.6 注意事项
- **首次启动**：Docker镜像构建约10-20分钟（需下载docling/deepeval/aider等依赖），后续启动秒级
- **API Key**：必须配置至少一个LLM API Key，否则Agent任务无法执行真实推理
- **GPU加速**：如有GPU，可将`DOC_PARSER_PROVIDER`改为`marker`，安装marker-pdf获得7.4页/秒解析速度
- **数据持久化**：所有数据通过Docker Volume持久化，`docker-compose down`不丢失数据

### 1.2 部署模式

| 模式 | 适用场景 | 配置要求 | 模型来源 |
| --- | --- | --- | --- |
| **全API模式**（MVP推荐） | 快速验证、POC、无GPU资源 | 8核CPU/32GB内存/200GB磁盘 | DeepSeek V4 API + Qwen API |
| **混合模式** | 生产交付、数据敏感 | 8核CPU/32GB + 1×A100(40GB) | 代码/设计用API，调研用本地Qwen3.6-27B |
| **全私有化模式** | 严格数据合规 | 16核CPU/64GB + 2×A100(80GB) | 全部本地部署（vLLM加载DeepSeek V4 Flash/Qwen3.6） |

MVP阶段推荐**全API模式**，降低部署门槛，快速验证业务流程。

### 5.2 Nginx配置要点

```nginx
# deploy/nginx.conf 核心配置
server {
    listen 80;
    server_name _;
    client_max_body_size 500m;        # 大文件上传

    # 静态文件
    location / {
        root /usr/share/nginx/html;
        try_files $uri $uri/ /index.html;
    }

    # API代理
    location /api/ {
        proxy_pass http://ai-fde-app:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 300s;       # 长任务超时
        proxy_buffering off;
    }

    # WebSocket代理
    location /ws/ {
        proxy_pass http://ai-fde-app:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 86400s;     # WebSocket长连接
    }

    # MinIO文件下载（代理，不暴露9000端口）
    location /files/ {
        proxy_pass http://minio:9000/aifde-documents/;
        proxy_set_header Host $host;
    }
}
```

## 6. 私有化部署（全本地模型模式）

### 6.1 部署架构调整
- 增加 `vllm` 服务，本地加载 Qwen3.6-27B（4bit量化，单张A100可跑）
- DeepSeek V4 Flash（284B/13B激活）需2×A100 80GB，MVP阶段建议用API
- 文档解析使用Marker v2 GPU模式

### 6.2 vLLM本地模型部署

```yaml
# deploy/docker-compose.gpu.yml 追加服务
services:
  vllm:
    image: vllm/vllm-openai:latest
    runtime: nvidia
    ports:
      - "8001:8000"
    environment:
      - MODEL_NAME=Qwen/Qwen3.6-27B
      - QUANTIZATION=fp8            # fp8 / awq / gptq
      - MAX_MODEL_LEN=32768
      - GPU_MEMORY_UTILIZATION=0.9
      - TENSOR_PARALLEL_SIZE=1
    volumes:
      - ./models:/root/.cache/huggingface
    deploy:
      resources:
        reservations:
          devices:
            - driver: nvidia
              count: 1
              capabilities: [gpu]
```

### 6.3 模型权重预下载

```bash
# 提前下载模型到本地（避免容器启动时下载）
mkdir -p deploy/models
docker run --rm -v ./models:/root/.cache/huggingface \
  huggingface/transformers-pytorch-gpu \
  python -c "from huggingface_hub import snapshot_download; snapshot_download('Qwen/Qwen3.6-27B')"
```

## 7. 数据备份与恢复

### 7.1 备份策略

| 数据 | 备份方式 | 频率 | 保留周期 |
| --- | --- | --- | --- |
| PostgreSQL | pg_dump全量 | 每天 | 30天 |
| Qdrant | snapshot快照 | 每周 | 90天 |
| MinIO | 文件同步 | 实时 | 永久 |
| 配置文件 | Git版本控制 | 每次变更 | 永久 |
| 项目代码 | Git仓库 | 每次提交 | 永久 |

### 7.2 备份脚本

```bash
#!/bin/bash
# deploy/backup.sh 每日备份脚本
set -e

BACKUP_DIR=/data/backups/$(date +%Y%m%d)
mkdir -p $BACKUP_DIR

# 1. PostgreSQL备份
docker exec postgresql pg_dump -U aifde aifde | gzip > $BACKUP_DIR/postgresql.sql.gz

# 2. Qdrant快照
docker exec qdrant qdrant snapshot create all_collections 2>/dev/null || true
docker cp qdrant:/qdrant/snapshots $BACKUP_DIR/qdrant-snapshots 2>/dev/null || true

# 3. MinIO备份
docker run --rm -v ./minio-data:/data -v $BACKUP_DIR:/backup \
  alpine tar czf /backup/minio.tar.gz -C /data .

# 4. 配置备份
cp .env $BACKUP_DIR/env.backup
cp docker-compose.yml $BACKUP_DIR/

# 5. 清理30天前的备份
find /data/backups -maxdepth 1 -type d -mtime +30 -exec rm -rf {} \;

echo "Backup completed: $BACKUP_DIR"
```

### 7.3 恢复流程

```bash
#!/bin/bash
# deploy/restore.sh 恢复脚本
# 用法: ./restore.sh /data/backups/20260901

BACKUP_DIR=$1

# 1. 停止应用服务
docker compose stop ai-fde-app

# 2. 恢复PostgreSQL
gunzip -c $BACKUP_DIR/postgresql.sql.gz | docker exec -i postgresql psql -U aifde -d aifde

# 3. 恢复MinIO
docker run --rm -v ./minio-data:/data -v $BACKUP_DIR:/backup \
  alpine sh -c "rm -rf /data/* && tar xzf /backup/minio.tar.gz -C /data"

# 4. 恢复配置
cp $BACKUP_DIR/env.backup .env
cp $BACKUP_DIR/docker-compose.yml .

# 5. 重启服务
docker compose up -d

echo "Restore completed from: $BACKUP_DIR"
```

## 10. 故障排查

### 10.1 常见问题

| 问题 | 可能原因 | 解决方法 |
| --- | --- | --- |
| 服务启动失败 | 端口被占用 | `lsof -i :8000` 查看占用，修改端口 |

## 11. 生产环境加固建议

1. **HTTPS加密**：配置SSL证书（Let's Encrypt / 商业证书），强制HTTPS跳转
2. **防火墙**：只开放80/443端口，数据库端口不对外暴露
3. **密码策略**：修改所有默认密码，使用强密码，定期轮换
4. **定期备份**：配置自动备份脚本，定期验证备份可恢复性
5. **日志审计**：开启操作审计日志，定期审查异常操作
6. **资源限制**：配置Docker容器资源限制，防止单服务耗尽资源
7. **安全扫描**：定期使用Trivy扫描Docker镜像漏洞
8. **监控告警**：配置Prometheus + Grafana监控，设置关键指标告警
9. **滚动更新**：生产环境使用蓝绿部署或滚动更新，避免停机
10. **灾备方案**：异地备份，制定灾难恢复预案并定期演练
