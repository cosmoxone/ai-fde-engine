## 1. 背景与目标

### 1.1 起点问题（Day 0 用户输入）

知识库负责同事（外部团队 kb-os）对两份设计文档提出 **5 条评审意见**：

1. 两份文档自相矛盾（curate 终态、stats coverage 口径不一致）
2. ingest 索引时效未定义（异步解析 ~18s，何时可检索？）
3. 错误码表未定义（HTTP 语义 + 稳定字符串码）
4. 鉴权强度不足（共享 token → 建议 scoped key）
5. 契约测试用例集请尽早提供（双实现对拍当验收用例）

### 1.2 目标链

```
消除文档矛盾 → 定版接口契约 → 双实现（Embedded 参考 / kb-os 真机）→ 契约测试对拍
→ 引擎接线（自动 ingest + 审核队列）→ 本体抽取（业务建模层）→ research RAG 化（消费侧）
```

### 1.3 约束与原则（全程不变）

- **模块分离**：知识库（存储检索层，可外置 kb-os）≠ 本体（业务建模层，留本项目）；互不 import，胶水走函数内 try-import
- **参考实现即规格**：Embedded 实现是契约行为基准，第三方实现以其对齐
- **永不阻断主流程**：知识库/本体故障不得阻断上传/修复等主链路（auto_ingest 永不抛、annotate 回退空、检索回退 full）
- **单机零依赖可跑**：无外部服务、无 LLM Key 时全流程 Mock 可通

## 2. 决策链复盘（问题 → 方案 → 理由 → 结果）

| # | 问题 | 决策 | 关键理由 | 结果 |
|---|---|---|---|---|
| D1 | 错误码形态之争（kb-os 数字码 40001 式 vs 我方字符串码） | **双轨**：契约/消费面稳定字符串码，kb-os Envelope 加 `error_key` 字段，适配器数字码映射兜底 | 可读性、可 grep、按 code 分支、行业惯例；不强迫对方改内部体系 | kb-os W1 上线 error_key；对拍 401/404/400 全通 |
| D2 | parsing 粒度（文档级 vs chunk 级） | **文档级**，三元不变量 documents+parsing+parse_failed=累计接受 | 单元一致性（入库/幂等/重试按文档）；chunk 级是"没有分母的进度条"；不泄漏切块内政 | 就绪判据 `parsing==0` 模式无关，对拍直接用 |
| D3 | ingest 协议（chunk 级推送 vs 文档级） | **文档级主协议**，chunk 级降级附录 A | 切块主权归知识库侧；参考实现补内嵌切块器保同构 | Embedded 同构实现，幂等按 doc_id |
| D4 | kb-os 接入方式（走法 A 薄适配 vs 走法 B 契约改造） | **走法 A**：KbOsGateway 消费 kb-os 原生 API | 单契约下 kb-os 的 request_id 审计/限流直接生效；~1 人日 | 对拍 13/13 验证 |
| D5 | RAG-less 趋势 vs RAG 化（用户质疑） | **有止损线的实验**：三模式开关 + 黄金集回归门槛 + 倒退回退全文；18 号 ADR 可证伪 | 趋势淘汰的是"无脑向量管线"而非"检索"动作；本项目场景（私有/时变/溯源/超预算）检索缩不掉；且现状是 `[:30000]` 截断真 bug | hybrid 默认落地，大语料 reduction>0.5 |
| D6 | 本体放哪（知识库侧 vs 本项目） | **留本项目**，`entity_hints` 可选 metadata 轻握手（"存而不滤"） | 本体与需求分析/人工编辑强耦合，是业务建模层；契约不绑定本体 | v0.4-b 零依赖 kb-os 完成 |
| D7 | 本体要不要对外独立服务（用户要求） | **三层镜像**：Embedded/Remote/Fallback + 独立 HTTP 服务 + 20 号契约 | 对称知识库模式；其他独立组件经 `/hints` 融合；将来可独立部署或换第三方 | 20 号 v0.1-draft 交付 |

**决策框架提炼**：每个争议先问"淘汰的是形态还是动作"（D5）、"单元一致性在哪一层"（D2）、"耦合的代价 vs 收益"（D6）、"谁是行为基准"（D3/D4）。能双轨不单选（D1），能实验不站队（D5）。

### 3.2 联调对拍期（W3）

**对方预演发现我方 bug**（最有价值的一课）：

- 现象：`test_stats_invariant_and_ready` 全套连跑挂、单跑过
- 根因：`before = kb.stats()` 裸快照——前一用例的 3 篇文档还在异步解析（parsing=3），delta 基线被污染；Embedded 同步索引（恒 parsing=0）**永不触发**
- 修复：`before = wait(kb)` 一行——快照前先收敛
- **意外收益**：修复后 delta 断言变相对基线，对脏库免疫——顺带消解了对方"联调需干净库"的前提
- 教训：**契约测试必须假设"实现是异步的"**（契约允许最终一致，用例就不能依赖同步实现的行为）；**跨测试状态污染是契约测试的头号缺陷源**（共享 fixture 的 marker 之前也坑过一次：按 marker 模糊断言 → 改为按 entry_id 精确断言）

**对拍执行纪律**：拿到 key 先 curl 三连（health / 带 key stats / 无 key 401）再跑套件；预期差异收敛在 Expectations 对象（如超批量：spec14 413 vs kbos 400），**场景内核零分叉**。

### 3.3 实施冲刺期（v0.4-a/b/c 一日三段）

节奏：**侦察 → 设计 → 连续落码 → 测试 → 文档登记** 五拍循环，每段结束全量回归 + CHANGELOG。三段共 +25 测试。

## 4. 排坑手册（现象 → 根因 → 解法 → 预防）

> 按"发现成本"排序，前面的最贵——本文存在的意义就是让后来的 Agent 免付这些成本。

### 4.1 环境类

| # | 现象 | 根因 | 解法 | 预防 |
|---|---|---|---|---|
| E1 | `ValueError: Unknown scheme for proxy URL socks://…` 构造 httpx.Client 即炸 | 本机 socks 代理环境变量毒化（`ALL_PROXY` 等） | 所有 `httpx.Client(..., trust_env=False)`（网关/适配器/MockTransport/probe 全部） | **任何出网客户端默认 trust_env=False**，测试机环境不可信 |（**黄金集终验时再犯一次**：llm/client.py 的 AsyncClient 当时漏改，症状是"评估 0.1s 跑完 + 命中率 47.89% 全 mock"——代理毒化会静默降级，务必全仓 grep `httpx` 构造点逐一核查） |
| E2 | uvicorn/python-multipart/aiofiles/jinja2/pyyaml/python-dotenv/python-docx 陆续 ImportError | 重建 dev venv 后依赖不全 | 逐个补装 | 冒烟命令（起服务 + 全量测试）进 checklist；venv 重建后先跑冒烟再干活 |

### 4.2 数据/契约行为类

| # | 现象 | 根因 | 解法 | 预防 |
|---|---|---|---|---|
| D-1 | FTS 查询 `IndexError: No item with that key`（row["score"]） | SELECT 列表里没有 score 列，却在 row 取 | rank 在调用侧归一化，`_fts_row_to_hit(row, score)` 显式传参 | 行对象取键前先看 SELECT |
| D-2 | 自然语言长句查询 0 命中（"需要一个来料检验智能助手"），单词查询正常 | Embedded 把整串查询当**单一 phrase** MATCH——trigram 连续匹配语义下长句几乎必不中 | 三级降级：整串 phrase → **分片 OR**（按标点/空白切，长片段优先）→ LIKE 兜底 | 检索实现的默认查询语义必须用"真实消费端查询形态"测试（RAG 的查询是自然语言，不是关键词）——这是 RAG 化实施时才暴露的潜伏缺陷 |
| D-3 | RAG 查询集 0 命中 → 全部回退 full | 查询集只有"诉求长句+文件名"——恰是 D-2 里命中率最低的两类 | 查询集补**文档内容首段**（首段通常含主题词） | 检索查询构造要"多样本"：标题/首段/诉求，多路召回 |
| D-4 | 测试断言 reduction>0.5 失败（实测 0.297） | 测试语料仅 3200 字——**撞上自家 ADR 的边界规则**（小语料本就该全文塞） | 测试改 3.5 万字大语料 | 断言阈值要与场景前提匹配；边界规则写进 ADR 的同时写进测试设计 |

### 4.3 测试工程类

| # | 现象 | 根因 | 解法 | 预防 |
|---|---|---|---|---|
| T-1 | 契约测试 12 个因服务已关挂 | 集成测试无环境守卫 | 模块级 `pytest.skip(allow_module_level=True)`（无 `KB_BASE_URL` 整模块跳） | 集成性质测试**必须有环境开关**，默认跳过 |
| T-2 | `asyncio.run() cannot be called from a running event loop` | 在 async 测试内同步 helper 里调 asyncio.run | helper 改 async，调用点 await | asyncio auto 模式下测试内禁用 asyncio.run |
| T-3 | patch 网关失败路径不生效（KB down 测试仍真连） | 函数内 `from ..knowledge import get_knowledge_gateway` 在**调用时**绑定源模块属性 | patch 源头：`patch("src.knowledge.get_knowledge_gateway")` 而非 gateway 子模块 | from-import 的 patch 目标看 import 发生处，不看定义处 |
| T-4 | **单跑过、全量挂**（settings_runtime 顺序耦合，耗时最长的坑） | 测试里 `get_settings.cache_clear()` 清掉全局单例 → 下游测试的 runtime 配置加载时序改变 | 删 cache_clear，改 `monkeypatch.setattr(agent.settings, "research_rag_mode", mode)`（实例属性，自动还原） | **测试永远不动全局缓存/单例生命周期**；改配置用 monkeypatch.setattr 定点注入 |
| T-5 | 测试间项目状态泄漏（fallback 用例不回退） | 多个用例共用同一 project_id，前者 seed 的 KB 数据污染后者 | 用例级独立 project_id（`kb-empty-proj`） | 共享 fixture + 共享 project 的组合要显式审查；**每个断言"空/失败"路径的用例用独立干净项目** |
| T-6 | Mock 断言挂：chunker 出 9 块（预期 1） | `"\n\n" "文本" * 8` 隐式字符串拼接后 `*8` 乘到整体 | 显式 `+` 连接 | 多段字面量拼接与 `*` 混用必须显式括号/+ |

### 4.4 工具类

| # | 现象 | 解法 | 预防 |
|---|---|---|---|
| W-1 | edit 工具多次 before/after 不匹配（文档已变/锚点被占/转义） | 改用 python heredoc 按精确原文 replace（带 assert 锚点存在）；或重新 grep 确认现状 | edit 失败两次即换 heredoc，不三连撞；**heredoc 里写正则/引号嵌套时警惕转义层**（本文档过程中正则字符类被 heredoc 转义搞坏一次——改用 unicode 转义写法 `\uFF0C` 稳过） |

## 5. 经验教训（分维度提炼）

### 架构

1. **契约与实现分离 + 参考实现即规格**：14 号契约（纯文本）+ Embedded（行为基准）+ 契约测试（场景内核 + 双断言适配）三件套，是双实现对拍能 13/13 的根基。差异点收敛在显式 Expectations 对象，不散落在用例里。
2. **Gateway 三态模式可复制**：Embedded（默认）/ Remote（URL 配置即启用）/ Fallback（远端故障降级 + degraded_since 标记 + 契约错误不降级）——v0.4-b 本体直接镜像此模式，成本 ~1/3（模式已验证，照抄即可）。
3. **降级链设计**：检索三级降级（phrase→分片 OR→LIKE）、RAG 三模式（full/hybrid/rag + 无命中自动回退）、本体不可用回退空——**每层能力的失效都有下一层接住**，且永不阻断主流程。
4. **轻握手优于强耦合**：本体×知识库只通过 `entity_hints` 一个"存而不滤"的可选字段连接，双方可独立演进（P2 才协商过滤）。

### 协作

5. **书面化 + 编号 + 异步优先**：所有立场落编号文档，会议只做形式确认（W0 从"决策会"降级为"15 分钟盖章"）；预演前移（对方 12/13 预演报告把对拍窗口的谈判变成了验证）。
6. **对方找出的我方 bug 是最高价值输入**：stats 用例缺陷由 kb-os 预演发现——根源是"用例写在自己实现的阴影下"。双实现对拍的本质价值：**用异构实现打掉同构盲区**。
7. **修复时顺手消解对方前提**：一行修复顺带让"干净库"前提失效并回执告知——修复的上限不是"变绿"，是"降低对方的运维成本"。

### 工程

8. **五拍节奏**：侦察（grep/sed 精准读）→ 设计（先定接口与验收）→ 连续落码（write/edit 批量）→ 测试（先跑新测再全量）→ 登记五处（契约/导读/roadmap/CHANGELOG/回执）。每拍结束有可验证产物。
9. **验收标准前置**：13 号排期表每行带验收列（实体≥20/关系≥15/不重复计数），实施时直接转测试断言——**验收先行，测试是验收的可执行形式**。
10. **ADR 可证伪**：18 号 RAG 立场文档写明"黄金集倒退即回退 + 数据推翻本文则以数据为准"，实施后补记——立场文档不是宣言是**带止损线的实验设计**。

### 测试

11. **测试隔离三件套**（conftest）：tmp 数据库（KNOWLEDGE_DB_PATH/ONTOLOGY_DB_PATH）+ 网关单例逐测试 reset + 集成测试环境开关（默认跳）。
12. **Mock 派生测试数据要"多文档可累积 + id 稳定"**：行业模板基础本体 + 文档标题派生实体（stable_id 哈希），保证幂等断言与规模断言同时成立。
13. **断言精确化**：状态断言用唯一 id 不用模糊 marker；delta 断言用相对基线（先收敛再快照）——两条都来自真实翻车。
