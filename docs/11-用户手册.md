# AI-FDE Engine 用户手册（FDE 视角）

> 适用版本：v0.1.3+ | 更新：2026-09-07 | 读者：使用本工具交付项目的 FDE
> 目标：**30 分钟内跑通首个项目全流程**（调研 → 方案 → Benchmark → 夜间迭代 → 导出交付物）

---

## 1. 安装启动（3 分钟）

### 方式 A：Docker（推荐）

```bash
docker run -d --name aifde -p 8000:8000 -v aifde-data:/app/data \
  ghcr.io/cosmoxone/ai-fde-engine:latest
```

打开 `http://localhost:8000/dashboard`。

### 方式 B：本地 Python

```bash
git clone https://github.com/cosmoxone/ai-fde-engine.git && cd ai-fde-engine
pip install -r requirements-core.txt
uvicorn src.main:app --port 8000
```

### 数据在哪？

- 业务数据（项目/任务/Benchmark/badcase/评审）：SQLite 单文件 `data/aifde.db`（Docker 中在 `aifde-data` 卷）
- 配置（LLM Key）：`data/settings.json`
- **重启/升级不丢数据**；备份 = 拷贝 `data/` 目录

## 2. 配置 LLM（1 分钟）

顶部提示条「当前为 Mock 模式」→ 点 **立即配置**：

1. 选择 Provider（DeepSeek 推荐 / Qwen）
2. 粘贴 API Key（[获取 DeepSeek Key](https://platform.deepseek.com/)）
3. 保存 → **立即热生效**，无需重启

> 不配置也能跑：全流程 Mock 模式（用于学习流程/演示），但输出为模拟内容。

## 3. 第一个项目全流程（约 25 分钟）

### Step 1 创建项目（1 分钟）

项目管理 → 新建项目：

| 字段 | 建议 |
| ---- | ---- |
| 行业 | **务必填写**：制造业/金融/政务会自动加载行业模板（知识上下文+行业 Benchmark 种子） |
| 名称/客户 | 按实际填写 |

### Step 2 上传客户文档（2 分钟）

项目详情 → 上传文档（支持 md/txt/pdf/docx 等）：

- 建议：业务流程说明、规章制度、产品手册、历史工单导出
- 没有文档？直接下一步——行业模板会提供种子内容

### Step 3 调研分析（真实 LLM 约 2-5 分钟 / Mock 数秒）

触发「调研分析」，Agent 产出**需求基线**：

- 业务流程（节点/痛点/自动化候选）
- 数据资产清单
- **Benchmark 验收标准**（验证前置：先定验收再开工）
- 功能需求清单（每条含量化验收标准）

### Step 4 ✏️ 修订并确认需求（5 分钟）— 关键动作

AI 产出是初稿，**你的修改才是基线**：

项目详情 → 「需求基线✏️」标签 → 每条需求点 **编辑**：

- 修订标题/描述，**重点打磨验收标准**（这是防扯皮的合同条款）
- 修改直接进入基线，后续导出均含最新内容

### Step 5 方案设计（3 分钟）

触发「方案设计」→ 产品/技术/验证三方案 + 交叉校验。
同样可编辑产品功能项（详情 → 方案导出前 PATCH 或直接核对）。

### Step 6 生成 Benchmark（1 分钟）

「生成 Benchmark」→ 50 条测试用例（高频 60% / 边界 30% / 对抗 10%）。
无文档时自动使用行业种子用例。

### Step 7 试运行与夜间迭代（5 分钟）

上线试运行后，收集坏例：

- **快速提交**：质量中心 → 「⚡提交 Badcase」（10 秒一条：输入/实际/期望/类型）
- **夜间迭代**：触发「夜间迭代」（无参数自动归集全部 open badcase）：
  - 可自动修复的（知识缺失/格式问题）→ 自动修复 + 回归
  - 不可自动修复的（规则冲突/能力边界）→ 输出**修复建议**（业务确认草稿/拒答话术），晨间 review 采纳
  - 质量门禁不达标 → 自动拦截不部署

### Step 8 导出交付物（2 分钟）

项目列表 → **📦 导出**（DOCX）→ zip 包含：

1. 项目概览
2. 需求基线（含量化验收标准——含你 Step 4 的修订）
3. 三方案设计
4. Benchmark 测试集
5. 夜间迭代报告
6. 评审记录

Word 可直接编辑 → 交付客户。

## 4. 日常工作流（上线后）

```
白天：客户用 → 遇到坏例 → ⚡10秒提交
夜间：触发/定时迭代 → 自动归因修复 or 生成建议
晨间：审核工作台 review → 采纳建议 → 导出迭代报告
```

审核工作台：每项 AI 产出（调研结果/方案/代码）需人工 Approve/Reject——**AI 主导，人做决策点**。

## 5. 常见问题（FAQ）

**Q: Mock 模式和真实模式输出差别大吗？**
Mock 是结构化模拟（流程可跑通、字段齐全但内容通用）；配置 Key 后为真实分析。用 `python -m src.evaluation.golden` 可评估真实输出质量（要点命中率，目标 ≥80%）。

**Q: 支持哪些 LLM？**
DeepSeek（推荐）、Qwen、OpenAI 兼容接口（含本地 vLLM/Ollama，base_url 指向本地即可）。

**Q: 数据安全？**
单机定位：所有数据本地（SQLite/JSON），文档不出本机。请勿将 API 端口暴露公网（无认证）。

**Q: 想用真实组件（Docling 解析/Qdrant 知识库）？**
见 [模块切换指南](05-模块切换指南.md)：`pip install -r requirements.txt` + `.env` 配置 provider，逐个切换可回滚。

**Q: 重启后项目还在吗？**
在。v0.1.1+ 默认 SQLite 持久化。

**Q: 如何自定义行业模板？**
`src/templates/packs/*.json` 可复制修改；重启生效。行业不匹配时不注入模板，正常通用流程。
