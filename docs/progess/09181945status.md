## ① 做了什么

**CE 侧（已提交）——25 号承诺的"装配机制"补齐，默认行为零变化（588 用例全绿）**：
- `src/auth` 替换 provider 注册表：`register_auth_provider(name, factory)` / `get_provider_factory` /
  `registered_providers` + `set_auth_provider(p)` 装配期注入（优先级：注入 > 环境注册名 > local > 回落）
- `AuthProvider` 协议补 `users_enabled: bool`（多用户档标记——内核归属/过滤行为的开关语义）
- `LocalAuthProvider.admin_needs_activation()` 公开别名
- 替换点契约测试（25 号 §7 口径）：注册选择 / 未注册回落**且提示运维** / 替换 provider 端到端
  （guard、项目矩阵、归属过滤 + **子进程按真实装配序**验证登录路由换血）

**TE 侧（ee/，gitignored 本地开发）**：
- `ee/src/auth/te_auth.py`：TE 认证装配。local=默认（复用 CE LocalAuthProvider 本地多用户档，**零代码复制、
  单一实现源**）；casdoor=M1 占位（`register_auth_provider("casdoor",…)` 注册后自动放行，测试已预演）
- `ee/src/main.py`：TE 应用入口（`uvicorn ee.src.main:app`）。默认 `LOCAL_USERS_ENABLED=true` + APP_NAME TE 品牌
- `ee/src/saas/gateway/`：TE 网关骨架第一块 `/api/te/info`（edition/认证形态/能力面，登录后可访问）
- `ee/tests/`（10 用例）：装配默认值、fail-fast 矩阵、多用户全流程（激活→邀请→成员→隔离→viewer 只读→邀请码一次性）、入口冒烟

**装配纪律（与 CE 宽松回落不同，TE 更严）**：
- 无管理员且无 `ADMIN_INVITE_CODE` → **启动即拒**（防锁死；管理员就位后可免码重启——实测过）
- `AUTH_PROVIDER=casdoor` 未落地 → 启动即拒（不无感降级到无认证档）
- 显式 `LOCAL_USERS_ENABLED=false` → 警告放行（仅限隔离开发）

## ③ 过程中的坑（沉淀）

1. **`get_settings.cache_clear()` 会孤儿化引用**：src.main 等模块在导入时绑定 settings 对象；测试里清缓存后
   重建，save 改新单例、/health 读旧引用 → 隔模块污染（test_settings_runtime 挂）。正解：**单例字段就地改写**
   （monkeypatch.setattr 自动还原），永不清 lru_cache。ee/tests/conftest 同口径。
2. **FastAPI 0.141 的 `include_router` 是惰性 `_IncludedRouter`**（无 `.path` 属性）——"扫 app.routes 断言路由存在"
   的写法失效，改用 HTTP 行为断言（401=存在且受保护 ≠ 404）。
3. **"整块替换"是装配期语义**：login_routes 在 src.main 导入时挂载一次，进程内事后换单例只换 guard 不换登录
   路由——契约测试用子进程按真实装配序（先 set_auth_provider 再 import src.main）验证。
