## ① "看不到用户管理、没有输密码过程" —— 这是设计的默认行为，不是丢了功能

**v0.5 的兼容红线**（25 号 §0）："不启用本地多用户 = 现单用户模式，零依赖不变"。你的实例没设 `LOCAL_USERS_ENABLED`，处于**单用户档**：内置 `local-admin`、无登录页、无用户表，左下角显示"👤 本地单用户"、成员管理导航强制隐藏——这正是"v0.4 行为零变化"验收的一部分。

**启用方法**（我刚在 8011 端口完整走通并截图验证，`/tmp/shot1~3.png`）：

```bash
# 停掉你现在的 ai-fde 实例，加两个环境变量重启（或写进 .env）
LOCAL_USERS_ENABLED=true ADMIN_INVITE_CODE=自选激活码 \
  .venv/bin/uvicorn src.main:app --host 0.0.0.0 --port 你的端口
```

之后：打开 `/api/v1/auth/login` → 首次填 **用户名+口令(≥8位)+管理员激活码** → 激活即登录 admin → 左下角变"👤 xxx（admin）"、侧栏出现**成员管理** → 页内生成邀请码 → 新用户凭码自助激活 → 给成员分配项目角色。

两个注意事项：
- **8010 端口上跑的不是 ai-fde-engine**（我验证过 `/api/v1/health` 和 `/` 都 404，像 kb-os 或其他服务）。你看到的 Dashboard 来自另一个实例，先 `pgrep -af uvicorn` 找到真实进程再决定在哪加变量。
- 老代码有个我刚修的 bug：新用户填激活码点"登录/激活"会一直报"用户名或口令错误"（后端返回 401，前端却判 403 才转激活流程）——**重启时务必用最新代码**（≥77e7b28）。
