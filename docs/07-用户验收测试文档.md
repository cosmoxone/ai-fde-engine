# AI-FDE Engine 用户验收测试文档（UAT）

> 文档版本：v1.0 | 日期：2026-09-06 | 状态：待验收
> 面向角色：FDE工程师 / 项目经理 / 客户业务方 / 系统管理员

## 1. UAT概述

### 1.1 验收目标
用户验收测试（UAT）是系统交付前的最后一道验证环节，由最终用户在真实使用场景下验证系统是否满足业务需求和使用期望。

### 1.2 验收角色与职责

| 角色 | 验收职责 | 参与场景 |
|------|----------|----------|
| **FDE工程师** | 验证核心交付流程是否可用、AI输出质量是否达标、操作是否流畅 | 全部核心场景 |
| **项目经理** | 验证项目管控功能、进度可视化、风险预警、报告生成 | 项目管控场景 |
| **客户业务方** | 验证业务文档解析准确性、试用体验、问题反馈流程 | 业务验证场景 |
| **系统管理员** | 验证部署简易性、监控告警、备份恢复、安全配置 | 运维场景 |

### 1.3 验收环境
- **预发布环境**：与生产配置一致，使用真实LLM API
- **测试数据**：客户提供的真实业务文档（脱敏）
- **验收周期**：建议3-5个工作日
- **验收方式**：按场景执行，记录实际结果与问题

### 1.4 验收通过标准
- P0场景全部通过（无阻塞性问题）
- P1场景通过率≥90%
- 无Critical/Major级别未修复缺陷
- FDE工程师确认核心交付流程可用于实际项目
- 性能指标满足需求文档要求
- 部署文档可指导独立完成部署

## 2. FDE工程师验收场景

### 场景UAT-FDE-01：新项目启动与调研分析

**场景描述**：FDE工程师拿到一个新客户项目，上传业务资料，验证AI能否自动完成调研分析并输出可验证需求基线。

**前置条件**：
- 系统已部署并正常运行
- 已准备客户业务文档（至少3份，含PDF/DOCX/TXT）
- 已配置LLM API Key（真实模式）

**验收步骤**：

| 步骤 | 操作 | 预期结果 | 实际结果 | 通过 |
|------|------|----------|----------|------|
| 1 | 创建新项目，填写项目名称/客户名称/行业 | 项目创建成功，返回项目ID | | □ |
| 2 | 上传3份不同格式的业务文档 | 文档上传成功，解析状态为已完成 | | □ |
| 3 | 填写客户核心需求描述 | 需求描述保存成功 | | □ |
| 4 | 触发调研分析，等待完成 | 调研任务执行完成，无报错 | | □ |
| 5 | 查看业务流程建模结果 | 输出包含流程节点（≥3个）、流向、痛点、自动化机会 | | □ |
| 6 | 查看数据资产梳理结果 | 输出包含数据集列表、质量评估、接入方案 | | □ |
| 7 | 查看Benchmark测试集 | 生成≥5个测试用例，包含高频/边界/对抗三类 | | □ |
| 8 | 查看需求规格列表 | 输出功能需求（≥3项），每项有ID/标题/优先级/验收标准 | | □ |
| 9 | 确认需求基线 | 输出标记为"可验证需求基线"，P0需求有量化验收标准 | | □ |

**验收要点**：
- 调研结果是否基于上传的真实文档内容，而非通用模板
- 业务流程节点是否与客户实际业务匹配
- 需求验收标准是否可量化、可测试
- Benchmark用例是否覆盖真实业务场景

**优先级**：P0 | 预计耗时：30分钟
