# 功能可用性矩阵与 FDE 使用指引

> 版本：**v1.0** | 日期：2026-09-18 | 基于：v0.5.0-dev（562 测试）
> 用途：**诚实盘点**——哪些功能完全可用、哪些配置后可用、哪些仅是 demo/编排位；
> 并给出 FDE 的标准使用顺序（围绕核心价值：**把用户需求转化为软件产品/解决方案**）
> 维护纪律：新功能合入时必须在本矩阵登记其真实可用级别

---

## 1. 可用性分级定义

| 级别 | 含义 | 判据 |
| --- | --- | --- |
| **✅ 完全可用** | 单机零配置即真实闭环，有测试覆盖 | 不需要任何外部系统/Key |
| **🔑 配置后可用** | 功能链路真实，需配外部依赖（LLM Key 等） | 配置即真，未配自动降级且如实标注 |
| **🧩 编排位（demo）** | 接口/数据结构就绪，等待外部系统对接 | 未配置时明确提示"待接入"，不假装成功 |
| **🚧 桩/受限** | 局部硬编码或模拟输出 | 桩位明确标注，不冒充真实 |

| 页面 | 数据真实性 |
| --- | --- |
| 总览/项目/任务/审核/经验库/自助交付 | 全部真实 API 数据 |

**一句话结论**：**主链（需求→基线→方案→交付物→知识沉淀）在单机 Mock 下全流程真实闭环**；
外部执行面（编码 nf/测试 RPA/部署）是**诚实标注的编排位**，接入即真，绝不假装成功。

## 3. FDE 使用指引（顺序设计）

**核心价值链**：用户需求 ─→（理解/结构化）─→ 需求基线 ─→（方案化）─→ 解决方案 ─→（落地）─→ 软件产品/交付物 ─→（沉淀）─→ 组织资产

### 3.1 标准使用顺序（单项目八步）

| 步 | 界面入口 | 做什么 | 产出（价值节点） | 依赖 |
| --- | --- | --- | --- | --- |
| ① | 项目管理 | 建项目（行业模板匹配） | 项目空间 | 无 |
| ② | 项目详情→上传 | 传客户材料（需求文档/访谈纪要/SOP） | **知识入库+本体抽取自动完成**（资产就绪） | 无 |
| ③ | 任务→调研 | 跑 research（hybrid 默认：检索+本体注入） | **需求基线 v1.0**（业务流程/数据资产/用例雏形/需求清单） | Mock 可用；🔑Key 后为真实深度分析 |
| ④ | 审核工作台 | 人工审需求基线（业务专家可参与——多用户档） | **基线定版**（客户可签字的版本） | 无 |
| ⑤ | 任务→设计 | 跑 design | 产品方案+技术方案（选型/模块/接口） | 同③ |
 | ⑥ | 质量中心 | 生成/审核 Benchmark 用例 | **量化验收标准**（后续验收依据） | 无 |
| ⑦ | 项目详情 | 实现路径三选：a) 人工实现 b) **导出 night-factory 工单**（自动编码编排位） c) 自助交付（客户参与） | 可运行交付物 | 🧩nf 为导出；部署为桩 |
| ⑧ | 交付+经验库 | 导出 7 类交付物 DOCX；验收；复盘沉淀 | **价值交付闭环**；经验入库（下个项目冷启动更快） | 无 |

### 3.2 使用节奏建议（FDE 视角）

- **每天**：总览页扫项目状态 → 审核工作台清待审（审核是人工价值闸口）→ 质量中心看 badcase
- **每项目启动**：②③ 连跑（上传即入库，调研立即受益于检索与本体——v0.4 已打通）
- **每项目收尾**：⑧ 复盘必做（经验库资产化是"越用越强"的来源）；badcase 闭环条目进待确认队列
- **Mock 起步，Key 升级**：演示/学习用 Mock 全流程；正式项目配 LLM Key（横幅消失=真实模式）
