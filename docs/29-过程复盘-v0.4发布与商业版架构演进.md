## 2. 主线一：v0.4.0 发布与 CI（发布链路方法论）

**流程**：本地预演 → commit → push → 观察 CI → tag → 触发 publish → 观察 GHCR。

**本地预演是本轮最大方法论贡献**：push 前跑 CI 同款命令（`ruff check`/`ruff format --check`/pytest 全量/docker build+容器冒烟），**当场拦下 12 处 lint 违规、31 文件 format 偏差、2 处版本号硬编码漏改**——push 后 CI 一次全绿，零红灯返工。CI 脚本即预演清单（`ci.yml` 四道门逐一复刻）。

**发布纪律**：发布整理窗口"只收口不开新功能"（机制 3 明确推迟下一轮）；tag 惯例延续（v0.3.0→v0.4.0）；Release notes 从 CHANGELOG 提炼（gh release create 一次成文）。

## 3. 主线二：商业版架构三版演进（本文最贵的素材）

**TE/CE 边界经三版演进收敛，每版被推翻的原因全程存档**（27 号 §1 完整表）：

| 版 | 方案 | 推翻原因 |
| --- | --- | --- |
| v1.0 | 实例隔离（每租户一 CE 容器） | 资源密度低、共享域跨实例、协作绕远——用户拍板"走传统 SaaS" |
| v1.1 | 单体多租户，多用户/OIDC **下沉 CE 内核** | **多租户是 TE 特性不应进开源版**——CE 被 SaaS 假设污染，违背 open-core |
| v1.2 ✅ | 单体多租户，CE 只留 **AuthProvider 替换点**，TE 整块替换 | 终态：商业特性以"内核替换点"接入而非"内核内置开关" |

同期的关联收敛：**TE 是单版本**（Lite/Pro=订阅档位=计量放行，非两个产品——修正一次拆档误读）；
**EE=数据完全独立**（本地/云端专属/混合三形态，非"本地部署专用"）；**D4 知识库分轨**（CE=Embedded 唯一推荐，TE=平台池默认）；
**nf/RPA 双版本特性**（26 号：CE 精简面冻结 × TE 完整面）；统一外部系统定型（CASDoor 认证 + Token Gateway 计费，CE 零代码对接）。

**可操作裁决依据**（27 号判定规则，后续新特性都用它切）：*该能力是否要求"单机用户不部署任何外部系统就能用"？是→CE；否→ee 层经替换点或契约面接入。*

**决策收敛节奏的启示**：本轮用户连续纠正三次方向（实例隔离→下沉→移出），每次纠正都**先改文档再改代码**（25 号 v1.0 写完细节被拍板撤销，v1.1 重写——看似浪费，实则 v1.0 成了决策链的考古层）。**AI 提方案、人拍方向、文档落档、代码跟进**——顺序不乱，返工可控。

## 4. 主线三：CE v0.5 认证实施（替换制落地）

25 号 v1.1 一阶段当日落地：`src/auth/`（AuthProvider Protocol + LocalAuthProvider 两档 + PBKDF2 + HMAC cookie 会话 + 邀请码流 + 登录页）；全局 auth_guard（白名单公开路径）；**单用户档 v0.4 行为零变化**（旧 554 测试原样通过是验收的一部分）。

两个实施坑（详见 §6）：include_router 导入时固化空路由→改为**固定路由结构+端点运行时取 provider**（这正是替换制的实现关键）；HTML 模板 `.format()` 吃掉 CSS 大括号→占位符 replace。

## 6. 排坑手册（本段增量 8 条）

| # | 现象 | 根因 | 解法 | 预防 |
| --- | --- | --- | --- | --- |
| P-1 | ECharts 图表文字消失/默认色 | **canvas 不支持 CSS 变量字符串**——批量色值替换波及 JS 字符串里的 'var(--x)' | cssVar() 运行时取值 helper | 全文件批量替换前 grep 非目标上下文（JS 字符串/属性值） |
| P-2 | 八步向导注入后不渲染 | replace 锚点（recent-activity innerHTML）与实际文本不符，注入静默失败 | grep 实际锚点后重新插入 | 大文本注入后**立即 grep 验证落点**，别信 replace 返回值 |
| P-3 | DOM 断言偶发 0 条目（函数/元素都存在） | **kill+重启间隙连到旧进程**（旧 HTML 无新代码） | URL 加时间戳参数强制刷新 + 重启后先验进程版本 | 服务重启后的首次验证先打版本端点确认身份 |
| P-4 | include_router 后多用户档 404 | 路由在**导入时**按当时配置（单用户）固化空表 | 固定路由结构+端点内运行时取 provider | 装配期与运行期配置可能不一致时，路由结构不依赖配置 |
| P-5 | 登录页样式全乱 | `_LOGIN_HTML.format()` 把 CSS 的 `{}` 当占位符 | 自定义占位符 + replace | HTML 模板永远不用 .format()（含大量花括号） |
| P-6 | 生成器 fixture 消费写法怪 → 缩进连环错 | 用 `next(iter([...]))` 消费 contextmanager | 返回 @contextmanager 工厂函数，调用方 with | 测试 client 工厂写成 contextmanager 从一开始就规范 |
| P-7 | venv 无 ruff/playwright/pillow | CI 工具链与本地 venv 不同步 | 按需补装（ruff 用系统 ~/.local 的） | 预演 CI 前先对齐工具链清单 |
| P-8 | 28 号文档漏登记导读 | 手工登记无清单 | 补登（本轮复盘顺带） | 文档新增→导读/CHANGELOG 登记**写入同一 todo 块**收尾勾选 |

## 7. 经验教训（本段提炼）

1. **决策考古学**：被推翻的方案版本**保留在变更记录里**（25/27 号做法）——三次演进链比"最终方案"对后来者的教育价值高一个量级；下次拍板时可引用"我们为什么不走那条路"。
2. **边界要落成判定规则**而非原则口号："单机零外部系统可用=CE"一句话裁决后续所有争议（D4 知识库分轨当场用它切）。
3. **发布前预演 = CI 脚本逐条复刻**：本地预演成本（~10 分钟）远低于 push 红灯的返工+信任成本。
4. **无视觉能力的 UI 工程三件套**：截图（给人看）+ 客观指标（亮度/对比度）+ DOM 断言（给自己验）——三者覆盖"改了什么、改对没有、渲染没有"。
5. **诚实盘点是最好的产品文档**：28 号四级矩阵把编排位/桩明确标出——用户信任来自"不假装成功"，与 RPA pending_integration 的设计哲学同源。
6. **AI×人的决策分工**：AI 出完整方案与反面分析、人拍方向与领域事实（CASDoor 已有、TE 是一个版本、nf/RPA 也有双版本问题）——**领域事实永远在人那里，方案空间在 AI 这里**。
7. **单用户兼容是改造类功能的验收项**：auth 落地时"旧 554 测试原样通过"与"新 8 个测试通过"同等重要——改造的第一验收是**不破坏存量**。
