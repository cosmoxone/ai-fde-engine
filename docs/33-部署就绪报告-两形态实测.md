# 部署就绪报告：两形态实测（CE 本地多用户 × TE SaaS）

> 版本：v1.0 | 日期：2026-09-20 | 结论：**两形态部署物齐备且当日实测通过**。
> 触发：对外发布计划需要"多租户 SaaS 版"与"本地部署多用户 CE 版"两种部署环境的脚本/文档/测试。

## 0. 前置答案：Embedded 进程内支持本体吗？

**支持**。本体与知识库同构三态：`EmbeddedOntologyGateway`（契约 20 参考实现，SQLite，
无 `ONTOLOGY_SERVICE_URL` 即默认进程内）/ `RemoteOntologyGateway`（配 URL+token 接独立
服务）/ `FallbackOntologyGateway`（远端不可用自动降级）。`src/ontology/server.py` 另备
独立服务形态（`uvicorn src.ontology.server:app`）。**CE 单容器零外部依赖 = 知识库+本体
双 Embedded**。

## 2. 形态 1：TE SaaS（CASDoor + TE，kb-os 可选）——✅ 实测通过

**部署物**（新增）：`ee/deploy/te-saas/`——docker-compose.yml（casdoor+te；te 端口 8014，
casdoor 17100）+ `Dockerfile.te`（CE 内核+ee 层；platform-auth-kit 以预置 wheel 安装——
跨仓可复现物）+ `bootstrap.sh`（首启引导：取 app-built-in 凭证写入 .env + 回调授权 +
grantTypes 配置）+ `casdoor-conf/app.conf`（sqlite）+ README（含生产清单）+
`Dockerfile.te.dockerignore`（per-Dockerfile ignore——根 ignore 排除 ee/，TE 构建覆盖）。

**实测链**（2026-09-20，双容器 healthy）：
1. 引导：up casdoor → `bootstrap.sh`（凭证+回调+grants 入 .env）→ up te
2. 三绿：health 200 / login **307→CASDoor authorize** / **Bearer `/api/te/info` 200**
   （provider=casdoor）+ `/api/te/kb/status` **mode=embedded**（kb-os 未配=对等模式，
   零外部依赖）+ 无凭据 401

**实测踩坑录**（已修入部署物，后人免踩）：
| # | 坑 | 修 |
| --- | --- | --- |
| 1 | 容器内小写 `http_proxy`（docker 注入）劫持 kit JWKS 获取（502） | compose 显式清空大小写代理变量 |
| 2 | CASDoor `origin` 即 token issuer——与 TE 校验 endpoint 不一致即 401 | app.conf origin=容器内名；生产=域名反代（README 生产清单） |
| 3 | 全新 CASDoor 实例 grantTypes 空（client_credentials 拒） | bootstrap.sh 一并配置 |
| 4 | compose build context 层级（te-saas 三层深）与 .dockerignore 互斥 | context=../../.. + per-Dockerfile ignore |

## 3. 两形态边界（选型）

| | 形态 2 CE 本地多用户 | 形态 1 TE SaaS |
| --- | --- | --- |
