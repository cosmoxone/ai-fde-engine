## 1. 总体架构

### 1.1 架构设计原则
- **Agent原生**：基于Pydantic AI V2的Capabilities机制，类型安全、可组合
- **记忆优先**：时序知识图谱作为一等公民，贯穿项目全生命周期
- **工具标准化**：所有外部能力通过MCP协议接入，可插拔替换
- **评测驱动**：DeepEval断言式评测嵌入开发全流程，质量门禁自动化
- **KISS**：MVP阶段只保留核心组件，避免过度设计

## 2. 核心模块详细设计

### 2.1 Agent层设计

#### 2.1.1 Agent基类（BaseAgent）
基于Pydantic AI V2的Agent类扩展，统一注入：
- 记忆Capability：自动注入项目上下文与历史经验
- 工具Capability：动态绑定MCP工具集
- 评测Capability：输出自动经过DeepEval断言校验
- 护栏Capability：敏感信息过滤、业务规则约束
- 可观测Capability：自动Trace到LangFuse

```python
class BaseAgent:
    """FDE Agent基类，统一注入横切能力"""
    agent: Agent  # Pydantic AI Agent
    project_id: str
    memory: MemoryManager
    tools: list[MCPTool]
    
    def __init__(self, project_id: str, model: str, tools: list):
        self.project_id = project_id
        self.memory = MemoryManager(project_id)
        # 构建Capabilities
        self.agent = Agent(
            model=model,
            capabilities=[
                MemoryCapability(self.memory),
                ToolCapability(tools),
                EvaluationCapability(),
                GuardrailCapability(),
                ObservabilityCapability(),
            ],
            system_prompt=self.get_system_prompt(),
        )
```

### 2.2 记忆层设计（核心创新）

#### 2.2.1 双层记忆架构

**第一层：Zep Graphiti 时序知识图谱（长期项目记忆）**
- 存储：PostgreSQL + 图扩展
- 数据模型：
  - 实体（Entity）：客户、业务系统、角色、文档、功能点、技术组件、问题、解决方案
  - 关系（Relation）：包含、依赖、解决、关联、属于、替代
  - 事件（Event）：带时间戳的项目动作（决策、变更、问题发现、修复）
  - 事实（Fact）：从文档/对话中抽取的业务规则与约束
- 核心能力：
  - 自动抽取：每轮Agent交互后自动抽取实体、关系、事件
  - 时序感知：支持"项目第3天决定了什么""上周发现了什么问题"类查询
  - 跨项目检索：新项目启动时检索相似行业、相似场景的历史项目
  - 知识更新：事实变更时自动标记旧事实为过时，保留演进轨迹
  - Consolidation：定期合并相似实体、抽象通用模式

**第二层：Letta 三级会话记忆（Agent运行时记忆）**
- Core Memory（核心记忆，~2000字符/块）：始终在上下文中，Agent可直接编辑，存当前项目关键信息
- Recall Memory（回忆记忆）：完整对话历史，支持日期和文本搜索，类似磁盘缓存
- Archival Memory（档案记忆）：工具访问的长期存储，类似冷存储，存项目详细资料
- Agent自主管理：通过工具调用在三层之间移动记忆块，Consolidation是涌现的而非定时的

#### 2.2.2 记忆管理器（MemoryManager）
```python
class MemoryManager:
    """统一管理双层记忆，对Agent透明"""
    project_id: str
    graphiti: ZepGraphitiClient  # 时序知识图谱
    letta: LettaClient            # 三级会话记忆
    
    async def remember(self, content: str, metadata: dict):
        """记录记忆：同时写入图谱（长期）和会话记忆（运行时）"""
        # 1. Letta写入对话历史
        await self.letta.add_message(content)
        # 2. Graphiti抽取实体关系事件，写入图谱
        await self.graphiti.add_fact(content, metadata)
    
    async def recall(self, query: str, limit: int = 10) -> list[Memory]:
        """检索记忆：图谱语义检索 + 会话记忆关键词检索，融合去重"""
        graph_results = await self.graphiti.search(query, limit)
        recall_results = await self.letta.search(query, limit)
        return self._merge_and_rank(graph_results, recall_results)
    
    async def get_project_context(self) -> str:
        """获取项目上下文：Core Memory + 图谱关键事实，注入Agent系统提示"""
        core = await self.letta.get_core_memory()
        key_facts = await self.graphiti.get_key_facts(self.project_id)
        return f"[项目核心信息]\n{core}\n\n[关键业务事实]\n{key_facts}"
    
    async def consolidate(self):
        """记忆巩固：合并相似实体、抽象通用模式、清理过时信息"""
        await self.graphiti.consolidate()
        await self.letta.consolidate()
```

#### 2.2.3 跨项目经验复用流程
1. 新项目启动时，输入客户行业与场景描述
2. MemoryManager从图谱中检索Top-5相似历史项目
3. 自动提取：相似方案、通用组件、常见坑点、Benchmark模板
4. 注入调研Agent的上下文，作为参考起点
5. 新项目过程中产生的新知识实时写回图谱

### 2.3 工具层设计（MCP化）

所有工具封装为标准MCP Server，通过MCP Gateway统一管理，Agent动态发现调用。

#### 2.3.1 文档解析MCP Server（doc-parser-mcp）
- 底层：Marker v2（主力，GPU加速）+ Docling（备选，表格场景）
- 接口：
  - `parse_document(file_path, options)` → 结构化JSON（段落、表格、图片、标题层级）
  - `parse_batch(file_paths)` → 批量解析
  - `extract_entities(content, domain)` → 业务实体抽取
- 输出格式：DoclingDocument JSON，含坐标、块ID、阅读顺序

#### 2.3.2 知识库MCP Server（knowledge-base-mcp）
- 底层：LightRAG + Qdrant
- 接口：
  - `create_kb(kb_name, config)` → 创建知识库
  - `add_documents(kb_id, file_paths)` → 增量添加文档（自动构建图谱）
  - `query(kb_id, question, top_k)` → 双层检索（关键词+实体关系）
  - `get_stats(kb_id)` → 知识库统计（实体数、关系数、文档数）
- 特点：无需调切片策略，上传文档自动构建知识图谱

#### 2.3.3 Benchmark MCP Server（benchmark-mcp）
- 底层：DeepEval Synthesizer + 双Agent对抗生成
- 接口：
  - `generate_testset(documents, config)` → 自动生成测试集（高频/边界/对抗三类）
  - `run_evaluation(testset_id, target_system)` → 跑批评测
  - `get_report(testset_id)` → 评测报告（准确率、幻觉率、召回率、Badcase清单）
  - `add_assertion(testset_id, rule)` → 添加业务规则断言
- 特点：对抗式生成，测试集覆盖度比人工高3倍

#### 2.3.4 代码生成MCP Server（code-gen-mcp）
- 底层：OpenHands SDK（主力）+ Aider（快速小迭代）
- 接口：
  - `generate_project(requirements, tech_stack)` → 端到端生成项目代码
  - `fix_issue(repo_path, issue_description)` → 修复指定问题
  - `refactor(repo_path, scope)` → 代码重构
  - `run_tests(repo_path)` → 运行测试并返回结果
- 沙箱：所有代码操作在Docker容器中执行，隔离安全

#### 2.3.5 数据探查MCP Server（data-explorer-mcp）
- 底层：DB-GPT Agent + SQLAlchemy
- 接口：
  - `connect_db(connection_string)` → 连接数据库
  - `explore_schema()` → 自动梳理表结构、字段、关系
  - `assess_data_quality(tables)` → 数据质量评估
  - `query_data(sql)` → 安全查询（只读、限流）
  - `generate_access_plan()` → 生成数据接入与脱敏方案

#### 2.3.6 部署MCP Server（deploy-mcp）
- 底层：Docker SDK + Argo Workflows
- 接口：
  - `build_image(repo_path, image_name)` → 构建Docker镜像
  - `deploy_compose(compose_path, env)` → Docker Compose部署
  - `get_logs(service_name)` → 获取服务日志
  - `rollback(version)` → 版本回滚
  - `health_check()` → 健康检查

### 2.4 评测与质量门禁设计

#### 2.4.1 评测体系（DeepEval驱动）
三层评测：
1. **单元级**：每个Agent输出经过断言校验（格式、业务规则、安全）
2. **集成级**：Benchmark测试集跑批，指标门禁
3. **系统级**：端到端场景测试，用户体验评估

核心指标：
| 指标 | 计算方式 | 门禁阈值 |
| --- | --- | --- |
| 业务准确率 | 正确答案数/总测试数 | ≥80% |
| 幻觉率 | 无依据输出数/总输出数 | ≤10% |
| 召回率 | 检索到相关文档数/相关文档总数 | ≥85% |
| 格式合规率 | 符合输出格式数/总输出数 | ≥95% |
| 安全合规率 | 通过安全检查数/总输出数 | 100% |

#### 2.4.2 质量门禁流程
```
代码提交 → 自动构建 → 单元测试 → DeepEval断言校验
    ↓ 通过
Benchmark跑批 → 指标对比基线 → 门禁判断
    ↓ 通过（指标不下降且达标）
自动部署测试环境 → 冒烟测试 → 版本发布
    ↓ 不通过
自动拦截 → 生成问题报告 → 通知人工审核
```

### 2.5 夜间迭代流水线设计（Argo Workflows）

DAG工作流定义：
```
[20:00 触发]
    ↓
[Step1: 数据归集] 收集当日Badcase、用户反馈、交互日志
    ↓
[Step2: 自动归因] DeliveryAgent分析Badcase，分类（知识库/Prompt/代码/规则/模型边界）
    ↓
[Step3: 自动修复] 并行处理：
    ├─ 知识库类 → LightRAG补充文档/更新图谱
    ├─ Prompt类 → 优化Prompt + 边界测试
    ├─ 代码类 → OpenHands修复Bug
    └─ 规则类 → 更新业务规则断言
    ↓
[Step4: 回归测试] 全量Benchmark跑批 + 新增Badcase专项测试
    ↓
[Step5: 门禁判断] 指标对比，通过则继续，不通过则回滚修复
    ↓
[Step6: 自动部署] 构建镜像 → 部署测试环境 → 冒烟验证
    ↓
[Step7: 版本报告] 生成迭代说明、指标对比、待确认问题清单
    ↓
[06:00 完成] 通知FDE早上审核
```

## 5. 安全设计

### 5.1 数据安全
- 客户文档传输加密（TLS 1.3），存储加密（AES-256）
- 数据库连接加密，敏感字段加密存储
- 代码Agent沙箱隔离（Docker容器，只读挂载，网络受限）
- 支持私有化部署，数据不出客户环境

### 5.2 访问控制
- RBAC角色权限：admin/fde/manager/client/viewer
- JWT Token认证，Token过期自动刷新
- API接口权限校验，操作审计日志
- MCP工具调用权限按Agent角色隔离

### 5.3 输出安全
- 敏感信息过滤：手机号、身份证、银行卡、API Key等自动脱敏
- Prompt注入防护：输入检测、输出校验
- 业务规则断言：DeepEval强制校验输出合规性
- 人工审核兜底：关键节点必须人工确认

## 6. 性能优化策略

### 6.1 模型推理优化
- 小模型优先：简单任务用Qwen3.6-27B，复杂任务用DeepSeek V4
- 批量处理：文档解析、Benchmark评测批量执行
- 缓存：相同查询结果缓存（Redis），避免重复推理
- 流式输出：Agent输出流式返回，减少等待感

### 6.2 知识库优化
- LightRAG增量索引，文档更新无需全量重建
- Qdrant量化（标量/乘积/二值），降低内存占用
- 热点知识预加载到Core Memory

### 6.3 并发优化
- 任务异步执行（Celery + Redis）
- Agent工具调用并行化
- 多项目资源隔离，GPU任务排队调度

## 7. 扩展性设计

### 7.1 模型可替换
- 统一LLM接口（兼容OpenAI格式），配置切换模型
- 支持本地部署模型（Ollama/vLLM）与API模型混合
- 模型路由：按任务类型自动选择最优模型

### 7.2 工具可扩展
- MCP标准协议，新工具只需实现MCP Server即可接入
- 工具动态发现，Agent运行时自动发现可用工具
- 工具权限按项目/角色配置

### 7.3 Agent可扩展
- 基于BaseAgent继承扩展新Agent类型
- Capabilities可组合，按需注入横切能力
- Agent模板库，行业专属Agent可配置化

## 8. 技术风险与应对

| 风险 | 影响 | 概率 | 应对措施 |
| --- | --- | --- | --- |
| LLM输出不可控 | 需求/方案质量差 | 高 | Pydantic类型校验+DeepEval断言+人工审核 |
| 长任务失败 | 迭代中断 | 中 | 任务拆解+断点续跑+超时重试+幂等设计 |
| 记忆幻觉 | 错误经验复用 | 中 | 记忆来源追溯+Consolidation校验+人工确认 |
| OpenHands稳定性 | 代码生成失败 | 中 | 多Agent备选（OpenCode/Cline）+人工兜底 |
| Marker中文效果 | 文档解析不准 | 中 | Docling备选+人工校对关键文档 |
| GPU资源不足 | 部署受限 | 中 | API模式优先+小模型本地+量化部署 |
