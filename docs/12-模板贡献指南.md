# 行业模板包贡献指南

> 欢迎为 AI-FDE Engine 贡献行业模板包！你所在行业的经验能帮助全球 FDE 少走弯路。
> 适用版本：v0.2.0+ | Issue 标签：`template`

## 模板包是什么

一个 JSON 文件 = 一个行业的交付知识包，创建项目时按行业自动注入：

- **research_hints**：调研 Agent 的行业上下文（业务节点/痛点/数据资产/合规/术语）
- **requirement_template**：功能需求示例条目（**必须含量化验收标准**）
- **benchmark_seed**：行业种子测试用例（**高频/边界/对抗三类**，对抗样例必须安全拒绝）
- **solution_skeleton**：常见模块与技术选型建议

## 快速开始（5 步）

```bash
# 1. 复制最接近的内置包
cp src/templates/packs/manufacturing.json src/templates/packs/your-industry.json

# 2. 用你的行业知识填充（字段说明见下）

# 3. 本地校验（质量红线）
python -m src.templates.validate src/templates/packs/your-industry.json

# 4. 确认内置包与你的新包都通过
python -m src.templates.validate   # 无参数=校验全部

# 5. 提 PR（标题：feat(template): 新增{行业}模板包）
```

## 字段规范

| 字段 | 必填 | 说明 |
| ---- | ---- | ---- |
| `key` | ✅ | 小写英文+连字符（如 `healthcare`），全局唯一 |
| `industry` | ✅ | 行业中文名（如 `医疗`） |
| `name` | ✅ | 模板名（如 `医院智能导诊与知识库模板`） |
| `aliases` | 建议 | 行业别名列表（中英文，如 `["医疗","医院","healthcare","三甲"]`），提高自动匹配率 |
| `research_hints.business_nodes` | ✅ | 该行业典型业务节点（5-8 个） |
| `research_hints.pain_points` | ✅ | 行业痛点（会被注入调研上下文） |
| `research_hints.data_assets` | ✅ | 常见数据系统/数据集 |
| `research_hints.compliance` | 金融/政务/医疗强烈建议 | 合规红线（会进入调研与 Benchmark 约束） |
| `research_hints.terminology` | 建议 | 术语表（缩写→全称），提升 LLM 理解 |
| `requirement_template[]` | ✅ ≥3 条 | 每条：id/title/description/priority/**acceptance_criteria（必须量化，含数字/比例/时限）** |
| `benchmark_seed[]` | ✅ ≥3 条 | 覆盖三类：`high_frequency`/`edge`/`adversarial` |
| `solution_skeleton` | 建议 | modules/tech_choices/integration |

## 质量红线（校验器强制）

1. **验证前置**：每条需求的验收标准必须量化（≥90%、≤3秒、缩短50%…）
2. **安全对抗**：对抗样例的 `expected_output` 必须是安全拒绝（含「无法/不能/请通过正规流程」类表述）——**绝不能示范违规操作**
3. **三类齐备**：Benchmark 种子必须同时含高频/边界/对抗
4. **脱敏**：所有内容不得含真实客户名称、真实人名、可识别的内部数据

## 评审标准

PR 评审关注（按优先级）：

1. 校验器全绿（硬门槛）
2. 行业真实性：业务节点/痛点是否来自真实交付经验（而非泛泛而谈）
3. 验收标准的量化质量：是否可直接作为合同附件
4. 对抗样例的行业相关性（不是通用安全拒绝，而是行业场景下的）
