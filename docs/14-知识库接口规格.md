# 知识库模块接口规格（KB Service API Spec）

> 版本：**v1.0-draft** | 日期：2026-09-16 | 状态：**待知识库团队评审**
> 用途：AI-FDE Engine（消费方）↔ 知识库独立模块（提供方）的对接契约。
> 你方可以：**按本规格实现**，或**提出修改意见**（回复本文档批注即可，双方确认后升版）。
> 行为基准：AI-FDE Engine 仓库内置 **Embedded 参考实现**（SQLite FTS5）实现同一契约，可作为语义参照与联调对照（见 §6）。

---

## 1. 总则

- **传输**：HTTP/1.1+，JSON（UTF-8）。生产建议部署于内网/容器网络。
- **基准地址**：`KNOWLEDGE_SERVICE_URL`（如 `http://kb:9000`），以下路径均相对该地址。
- **鉴权**（v1.0 可选，预留）：`Authorization: Bearer <token>`，token 由环境变量 `KNOWLEDGE_SERVICE_TOKEN` 双方共享。
- **幂等性**：`ingest` 按 `chunk.id` 幂等（重复推送去重）；`curate/confirm` 按 `entry_id` 幂等。
- **项目隔离**：所有操作带 `project_id`，知识库内部按其隔离数据。
- **错误格式**：非 2xx 时返回 `{"error": {"code": str, "message": str}}`；消费方按 `code` 分支处理。
- **分页**：pending 列表支持 `?limit=&cursor=`（简单游标），其余端点数据量可控暂不分页。

## 2. 端点优先级

| 优先级 | 端点 | 说明 |
| --- | --- | --- |
| **P0（联调最小集）** | `POST /ingest`、`POST /search`、`GET /stats` | 打通上传→建库→检索闭环 |
| **P1（交互闭环）** | `POST /curate`、`GET /pending`、`POST /entries/{id}/confirm|reject` | 打通人工审核→入库回流 |
| P2（增强） | filter 过滤、批量 confirm、webhook 回调 | 按需协商 |

**建议协作路径**：你方先交付 P0 三端点 → 双方联调（我方切 `KNOWLEDGE_SERVICE_URL` 实测）→ P1 → 收尾增强。

## 3. 端点详细规格

### 3.1 `POST /ingest` — 文档块入库（前期处理产物推送）

请求：
```json
POST /ingest
{
  "project_id": "p-uuid",
  "chunks": [
    {
      "id": "doc-uuid:para-12",
      "content": "A类物料按GB/T 2828.1抽样，AQL=0.65……",
      "source": {"filename": "质检手册.md", "para_idx": 12, "doc_id": "doc-uuid"},
      "metadata": {"title_path": "第3章>来料检验", "entity_hints": ["物料", "AQL"]}
    }
  ]
}
```

响应 `200`：
```json
{"accepted": 48, "deduped": 2}
```

语义与要求：
- `chunk.id` 全局唯一且稳定（我方按 `doc_id:para-N` 生成）——用于幂等与溯源
- `source` 必须原样保存并在 search 结果中返回（**溯源是卖点2的核心诉求**）
- `metadata.entity_hints` 为我方前期预标注（可选），你方可用于 schema/过滤增强，亦可忽略
- 单次请求上限 500 块；超限我方自动分批
- 实现建议：content 建立全文索引（FTS/向量均可，你方内政）

### 3.2 `POST /search` — 检索

请求：
```json
POST /search
{
  "project_id": "p-uuid",
  "query": "特采放行的审批流程",
  "top_k": 5,
  "filter": {"entry_type": "chunk|curated|any", "entity_type": null}
}
```

响应 `200`：
```json
{
  "hits": [
    {
      "content": "让步放行需取得客户书面特采许可，经MRB评审……",
      "source": {"filename": "质检手册.md", "para_idx": 34, "doc_id": "doc-uuid"},
      "score": 0.87,
      "entry_type": "chunk"
    }
  ]
}
```

语义与要求：
- `filter.entity_type` 为 P2 可选项（本体 schema 过滤），v1.0 可忽略该字段
- `score` 归一化 0-1（相对排序值即可，仅用于我方展示）
- 中文检索质量要求：能按语义/关键词命中段落（FTS trigram/BM25 或向量均可，你方选型）
- 空结果返回 `{"hits": []}`，不报错

### 3.3 `POST /curate` — 提交结构化知识条目草稿

请求：
```json
POST /curate
{
  "project_id": "p-uuid",
  "entry": {
    "question_pattern": "表面光洁度不达标但尺寸合格能否放行？",
    "answer": "不能直接放行。需提交MRB评审，取得客户书面特采许可后方可放行，并记录追溯。",
    "origin": "badcase:bc-uuid",
    "suggested_by": "nightly-iteration"
  }
}
```

响应 `200`：`{"entry_id": "ke-uuid", "status": "pending"}`

语义：**提交即 pending（待人工确认），不直接生效**。确认后（§3.5）该条目进入检索池（`entry_type: curated`，检索时优先级建议高于普通 chunk）。

### 3.4 `GET /pending` — 待确认队列（交互处理数据源）

`GET /pending?project_id=p-uuid&limit=50`

响应：
```json
{
  "entries": [
    {"id": "ke-uuid", "draft": {"question_pattern": "...", "answer": "...", "origin": "badcase:bc-uuid"}, "created_at": 1697...}
  ],
  "next_cursor": null
}
```

### 3.5 `POST /entries/{id}/confirm` / `POST /entries/{id}/reject`

请求（confirm 可带人工编辑后的终稿）：
```json
POST /entries/ke-uuid/confirm
{"entry": {"question_pattern": "...", "answer": "（FDE 修订后的终稿）..."}}
```

响应 `200`：`{"entry_id": "ke-uuid", "status": "confirmed"}`
语义：confirm 后条目进入检索池；reject 后保留记录但不再生效（`status: rejected`，可审计）。

### 3.6 `GET /stats` — 统计

`GET /stats?project_id=p-uuid` → `{"chunks": 1523, "curated": 18, "pending": 3}`

## 4. 典型时序（联调用例）

```
① 上传闭环（P0）：
  FDE上传文档 → Engine解析切块 → POST /ingest → POST /search "抽样方案" → 返回带source命中

② 交互闭环（P1）：
  夜间迭代发现知识缺失badcase → POST /curate（草稿）→ GET /pending（Dashboard展示）
  → FDE确认/编辑 → POST /entries/{id}/confirm → 检索命中该条目（entry_type: curated）
```

## 5. 环境与部署约定

- 我方通过 `KNOWLEDGE_SERVICE_URL` / `KNOWLEDGE_SERVICE_TOKEN` 环境变量接入（热切换不改代码）
- 连接语义：超时 5s（ingest 30s），失败我方自动降级 Embedded 参考实现并标记数据延迟（不阻断主流程）
- 健康检查：建议你方提供 `GET /health`（我方 Dashboard 状态页将展示）

## 6. 参考实现与联调支持

- 我方仓库内置 **EmbeddedKnowledgeGateway**（SQLite FTS5 trigram）实现同一契约（v0.4-a 交付），可作：
  - 语义对照（同一输入两实现输出可比对）
  - 你方未就绪期间我方开发不受阻（零依赖兜底）
- 联调物料：我方提供契约测试用例集（pytest，双实现共用），你方可直接拿去当验收用例
- 问题反馈：本文档批注 / 双方联调会

## 7. 版本与变更

- 本规格与 [13-本体与知识库深化设计](13-本体与知识库深化设计.md) §3.1 同源，端点变更需双方确认后同步升版
- 兼容策略：新增字段向后兼容（消费方忽略未知字段）；破坏性变更需提前一个 minor 版本 deprecation 通知
