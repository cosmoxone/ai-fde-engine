## 1. 总则

- **传输**：HTTP/1.1+，JSON（UTF-8）。生产建议部署于内网/容器网络。
- **基准地址**：`KNOWLEDGE_SERVICE_URL`（如 `http://kbgw:8010`），以下路径均相对该地址。
- **鉴权（v1.2 定版）**：Scoped API Key——**每项目一把、可吊销、带能力域**；`Authorization: Bearer <scoped_key>`；**key 即项目身份，请求体不再携带 `project_id`**。
  - 能力域：`kb:read`（search / stats / pending / health / 文档回查）、`kb:write`（ingest / curate）、`kb:admin`（confirm / reject）；
  - key 绑定单一项目，跨项目访问 → `403 scope_denied`；凭证缺失/无效/已吊销 → `401 unauthorized`；
  - key 的签发/吊销/轮换属提供方内政（kb-os 承担发放，联调期 1 个工作日响应）；
  - 共享 token 自 v1.2 起从 HTTP 契约移除（未发布过，pre-GA 修订）；Embedded 进程内模式无 HTTP 鉴权，项目上下文由 `KnowledgeGateway` 抽象内部管理。
- **索引时效（最终一致）**：`POST /ingest` 返回 200 仅表示**已持久接受并进入解析/索引管线**，不承诺立即可检索。就绪判据：`GET /stats` 的 **`parsing == 0`**（模式无关）。同步实现（直写即索引）恒为 0，同样合规。**消费方不得把最终一致窗口误判为数据缺失**。
- **幂等性**：`ingest` 按 `metadata.doc_id` 幂等（缺省 title+内容哈希；重复推送计入 `deduped`）；`curate` 按 `origin + question_pattern` 幂等（返回既有 `entry_id`）；`confirm/reject` 按目标终态幂等（重复调用返回当前终态，200）。
- **项目隔离**：由 Scoped API Key 在鉴权层强制（错传只可能查无数据，不可能横向越权）。
- **错误格式**：非 2xx 时返回 `{"error": {"code": str, "message": str}}`；**`code` 为稳定字符串码，枚举见 §4**；未知 `code` 按 HTTP 状态兜底。
- **分页**：pending 列表采用页码分页 `?page=&page_size=`（响应含 `total`）；其余端点数据量可控暂不分页。

## 2. 端点优先级

| 优先级 | 端点 | 能力域 | 说明 |
| --- | --- | --- | --- |
| **P0（联调最小集）** | `POST /ingest` | kb:write | 文档级推送（主协议） |
| **P0（联调最小集）** | `POST /search` | kb:read | 检索（溯源五字段必填） |
| **P0（联调最小集）** | `GET /stats` | kb:read | 统计 + 就绪信号（`parsing`） |
| **P1（交互闭环）** | `POST /curate`、`GET /pending` | kb:write / kb:read | 审核→回流入池 |

## 3. 端点详细规格

### 3.1 `POST /ingest` — 文档入库（文档级推送，主协议）

请求：
```json
POST /ingest
{
  "documents": [
    {
      "title": "质检手册.md",
      "content": "A类物料按GB/T 2828.1抽样，AQL=0.65……（整篇原文）",
      "metadata": {"doc_id": "doc-uuid", "title_path": "第3章>来料检验",
                   "entity_hints": ["物料", "AQL"], "origin": "fde-upload"}
    }
  ]
}
```

响应 `200`：
```json
{"accepted": 1, "deduped": 0}
```

语义与要求：
- **文档级语义**：解析/切块/向量化由知识库侧完成（切块主权归提供方——语义切块、自动 Summary 等能力由此保留）；`content` 为整篇原文（文本/Markdown）
- **幂等按 `metadata.doc_id`**（缺省 title+内容哈希）；重复推送同 doc_id → `deduped+1`；"重传半份文档"不是合法状态
- **时效**：200 = 持久接受 + 排队解析，最终一致（§1）；消费方检索前轮询 `stats.parsing == 0`
- `metadata` 全量保存并于检索结果 `custom_metadata` 原样回带（`entity_hints` 存而不滤，为本体过滤 P2 预留；`title_path`/`origin` 溯源用）
- 单批 ≤ 50 篇文档，超限返回 `413 payload_too_large`（消费方自动分批）
- 可选响应扩展：`items: [{title, knowledge_id, parse_status}]`（逐篇解析状态，kb-os 已提供）
- 降级模式（chunk 级推送）：见附录 A——仅在消费方切块管线有已投产复用刚需时使用，检索质量预期书面调低

### 3.2 `POST /search` — 检索

请求：
```json
POST /search
{
  "query": "特采放行的审批流程",
  "top_k": 5,
  "filter": {"entry_type": "chunk|curated|any"}
}
```

响应 `200`：
```json
{
  "hits": [
    {
      "content": "让步放行需取得客户书面特采许可，经MRB评审……",
      "source": {
        "filename": "质检手册.md",
        "chunk_index": 34,
        "start_at": 8210,
        "end_at": 8790,
        "knowledge_id": "k-…"
      },
      "score": 0.87,
      "entry_type": "chunk"
    }
  ]
}
```

语义与要求：
- **溯源五字段必填**：`filename / chunk_index / start_at / end_at / knowledge_id`（**合同级验收的核心诉求**）；坐标由知识库生成，引擎侧重切块后依然可信；`knowledge_id` 配合 `GET /documents/{knowledge_id}` 回查原文
- `entry_type`：`chunk`（文档切片，含提供方生成的 Summary 切片）｜`curated`（人工确认的知识条目）
- `score` 归一化 0-1（相对排序值，仅用于展示）
- **curated 排序语义**：推荐加权 + 反馈学习（LTR），同分时 curated 先出——不固定置顶（欠佳条目霸榜无自愈路径）
- 中文检索质量要求：语义/关键词混合命中（向量+BM25 或 FTS 均可，提供方选型）
- 空结果返回 `{"hits": []}`，不报错

### 3.3 `POST /curate` — 提交结构化知识条目草稿

请求：
```json
POST /curate
{
  "entry": {
    "question_pattern": "表面光洁度不达标但尺寸合格能否放行？",
    "answer": "不能直接放行。需提交MRB评审，取得客户书面特采许可后方可放行，并记录追溯。",
    "origin": "badcase:bc-uuid",
    "suggested_by": "nightly-iteration",
    "similar_questions": ["光洁度超差但尺寸合格可以放行吗"]
  }
}
```

响应 `200`：`{"entry_id": "ke-uuid", "status": "pending"}`

语义：**提交即 pending（待人工确认），不进检索池**；确认后（§3.5）进入检索池（`entry_type: curated`）。`similar_questions`（可选）为语义扩展问法，提升召回。幂等：同 `origin + question_pattern` 重复提交返回既有 `entry_id`。

### 3.4 `GET /pending` — 待确认队列（交互处理数据源）

`GET /pending?page=1&page_size=50`

响应：
```json
{
  "total": 3, "page": 1, "page_size": 50,
  "entries": [
    {"entry_id": "ke-uuid", "draft": {"question_pattern": "...", "answer": "...", "origin": "badcase:bc-uuid"}, "created_at": 1697…}
  ]
}
```

### 3.5 `POST /entries/{id}/confirm` / `POST /entries/{id}/reject`

请求（confirm 可带人工编辑后的终稿）：
```json
POST /entries/ke-uuid/confirm
{"question_pattern": "...", "answer": "（FDE 修订后的终稿）..."}
```

响应 `200`：`{"entry_id": "ke-uuid", "status": "confirmed"}`

语义：
- confirm 后条目进入检索池（最终一致口径同样适用；提供方同步直写则即时生效）；reject 后保留记录可审计、不再生效（`status: rejected`，reject 可带 `reason`）
- **终态不可逆**：已 confirm/reject 的条目再操作返回当前终态（幂等 200）；`rejected` 条目不可再 confirm
- 条目不存在 / 终态条目收到不可变更操作 → `404 not_found`

### 3.6 `GET /stats` — 统计与就绪信号

`GET /stats` →
```json
{"documents": 1523, "parsing": 2, "curated": 18, "pending": 3,
 "chunks": 8412, "parse_failed": 0, "rejected": 1}
```

字段口径（**联调与对拍判定基准**）：

| 字段 | 必填 | 口径 |
| --- | --- | --- |
| `documents` | ✅ | 已完成解析索引、**可被检索命中**的文档数 |
| `parsing` | ✅ | 已持久接受、**尚未完成索引的入库单元数**（主协议单元=文档；降级模式单元=chunk）；failed 不计入 |
| `curated` | ✅ | `confirmed` 条目数 |
| `pending` | ✅ | `pending` 条目数 |
| `chunks` | 可选 | chunk 总数（提供方切块内政的近似计数，仅供展示，不得作为契约判据） |
| `parse_failed` | 可选 | 解析失败数（可重推）——"静默丢文档"检测 |
| `rejected` | 可选 | `rejected` 条目数 |

- **三元不变量**：`documents + parsing + parse_failed = 累计已接受文档数`（联调核账用；`parse_failed` 缺省按 0 计）
- **就绪判据**：`parsing == 0` ⇔ 全部已接受内容可检索（两种模式下均成立）

## 4. 错误码表（v1.2 定版）

错误响应统一为 `{"error": {"code": str, "message": str}}`；`code` 为稳定字符串码（小写下划线，双方按 code 分支），`message` 面向人、可变。未知 `code` 按 HTTP 状态兜底。新增 `code` 需双方协商随版本发布；不得复用既有 `code` 表达新语义。

| HTTP | `code`（字符串码） | kb-os 数字码（映射参考） | 触发场景 | 消费方处置 |
| --- | --- | --- | --- | --- |
| 400 | `invalid_request` | 40001 | 请求体不合契约（缺 `query`/`content` 等结构错误）；或超批量的提供方等价实现 | 修正请求，勿重试 |
| 400 | `invalid_chunk` | 40001 | 附录 A 降级模式：chunk 缺 `id`/`content`、同 id 不同内容 | 修正数据，勿重试 |
| 401 | `unauthorized` | 40101 | 凭证缺失/无效/已吊销 | 检查配置；连续出现告警；降级 Embedded |
| 403 | `scope_denied` | 40301 | 能力域不足 / 跨项目访问 | 检查 key 授权，勿重试 |
| 404 | `not_found` | 40401 | 库/文档/条目不存在，或终态条目收到不可变更操作（**资源类型入 message**；v1.1 `entry_not_found` 之泛化） | 修正 ID，勿重试 |
| 413 | `payload_too_large` | —（kb-os 侧以 40001 等价） | 单批 documents > 50 / chunks > 500 | 消费方自动分批（已实现） |
| 429 | `quota_exceeded` | 42901 | 配额/限流 | 指数退避重试（幂等保障安全） |
| 500 | `internal_error` | 50001 | 提供方内部错误 | 重试一次，持续则告警 |
| 500 | `misconfigured` | 50003 | 提供方写入侧/反馈环配置错误（**v1.2 新增**，与 `internal_error` 分支区分） | 联系运维，勿重试 |
| 503 | `service_degraded` | 50002 | 索引后端不可用等降级态 | 触发 Embedded 降级并标记数据延迟 |

**kb-os 双轨说明**：其 Envelope 数字 `code` 面向存量消费方（MCP/OpenClaw/内部审计）保持不变；同时自 W1 起提供可选字符串字段 `error_key`（与上表字符串码一致），`KbOsGateway` 直读 `error_key`、数字映射表仅作兜底（映射列见上表）。

## 5. 典型时序（联调用例）

```
① 上传闭环（P0）：
  FDE上传文档 → Engine 前期处理（元数据预标注，不切块）
  → POST /ingest（文档级，200=持久接受）
  → 轮询 GET /stats 至 parsing == 0（最终一致等待）
  → POST /search "抽样方案" → 命中带溯源五字段 → 必要时 GET /documents/{id} 回查原文

② 交互闭环（P1）：
  夜间迭代发现知识缺失badcase → POST /curate（草稿，status=pending）
  → GET /pending（Dashboard 审核队列，页码分页）
  → FDE确认/编辑 → POST /entries/{id}/confirm
  → 检索命中该条目（entry_type: curated，推荐加权出前列）
```

## 6. 环境与部署约定

- 我方通过 `KNOWLEDGE_SERVICE_URL` / `KNOWLEDGE_SERVICE_TOKEN` 环境变量接入（热切换不改代码；TOKEN 值 = 项目 scoped key）
- 连接语义：超时 search 5s / ingest 30s；连接失败或 `service_degraded` → 我方自动降级 Embedded 参考实现并标记数据延迟（不阻断主流程）
- 健康检查：`GET /health` → `{"status": "ok|degraded", "version": "<语义化版本>"}`（我方 Dashboard 状态页展示）

## 附录 A：chunk 级降级模式（`POST /ingest/chunks`）

> 仅当消费方已有投产的切块管线且必须复用时使用（09 方案 决策1.5）。**双方书面确认：该模式下提供方的 Summary chunk / Wiki 编译 / 语义切块三项能力失效，检索质量预期相应调低。**

请求：
```json
POST /ingest/chunks
{
  "chunks": [
    {"id": "doc-uuid:para-12", "content": "…", "source": {"filename": "…", "para_idx": 12, "doc_id": "doc-uuid"},
```
