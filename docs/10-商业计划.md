## 1. 执行摘要

**一句话定位**：AI-FDE Engine 是「AI 落地交付方法论的完整工具化」——把 FDE 从手工作坊升级为流水线作业的单机开源工具 + 团队商业版。

**商业模式**：Open-Core 双轨
- **Community Edition（CE，MIT 开源）**：单机、单用户、全核心功能免费——获客、信任、生态
- **Team Edition（TE，订阅）**：多用户协作、团队经验库、集中管控——主要营收
- **Enterprise Edition（EE，私有一口价）**：多租户 SaaS 化、白标、审计合规——大客户营收
- **增值线**：行业模板包、FDE 认证培训、云托管、实施服务

**核心商业逻辑（卖铲子逻辑）**：一个 AI 落地项目客单价 10-50 万元，一名 FDE 月人力成本 3-5 万元。工具只要帮 FDE「多并行 1 个项目」或「交付周期缩短 30%」，每月创造数万元增量价值；按席位收费每月数百元，价值取率不到 1%——付费意愿天然成立。

## 2. 目标用户与痛点分析

### 2.1 用户分层（从候选人到团队的金字塔）

```
        ┌─────────────────────┐
        │  L3 交付型公司/集成商  │  10-100人FDE团队，要白标、要SaaS化自助交付
        ├─────────────────────┤
        │  L2 AI落地团队        │  3-20人，多项目并行，要协作与经验共享
        ├─────────────────────┤
        │  L1 在职FDE/独立顾问  │  1-3人，接单交付，要效率要交付质量
        ├─────────────────────┤
        │  L0 FDE候选人/新人    │  想入行AI落地，要学习路径、要作品集
        └─────────────────────┘
   L0/L1 → CE 开源版（免费，最大公约数）
   L2   → TE 订阅（核心营收）
   L3   → EE 私有化 + 实施（大客单）
```

### 2.2 FDE 候选人（L0）的痛点 —— 未来的入行者

| 痛点 | 现状 | 工具价值 |
| ---- | ---- | ---- |
| **不知道 FDE 干什么** | 岗位描述模糊，网上没有体系化材料 | 系统内置完整交付方法论（调研→方案→交付→迭代），**用工具就是学方法论** |
| **学习曲线陡** | 自学拼凑：论文+博客+视频，6 个月摸不到门 | F8 培训模块：6 周成长路径 + AI 教练 + 沙箱实战（已实现骨架） |
| **没有作品集** | 面试拿不出交付物证据 | 每个项目产出标准化交付物（需求基线/方案/评测报告）→ 直接进简历 |
| **入行即内卷** | 只会调 API 的"提示词工程师"过剩 | 掌握「验证前置+质量门禁」的交付型能力，差异化竞争力 |

> **L0 是长期获客漏斗的入口**：今天用免费版学习的学生/转行者，三年后是带团队采购 TE 的决策者。

### 2.3 在职 FDE / 独立顾问（L1）的痛点 —— 核心用户

| 痛点 | 量化现状 | 工具价值（对应功能） |
| ---- | ---- | ---- |
| **调研慢** | 2 周读完客户文档、梳理流程 | 文档批量解析+流程建模+数据梳理：**2 周 → 半天**（F1） |
| **方案写作苦** | 产品/技术/验证三方案 1 周 | 三方案并行生成+交叉校验：**1 周 → 1 小时初稿**（F2） |
| **需求扯皮** | 验收标准后置，交付时扯皮 | **Benchmark 先行**：开工前生成测试集+量化验收标准（F1.4，方法论核心） |
| **单兵天花板** | 1 人同时只能 1-2 个项目 | AI 主导+人审核：**1 人并行 3-5 个项目**（全流程） |
| **返工返到吐** | 上线后 badcase 雪崩 | 质量门禁+夜间自动归因修复建议：**回归拦截+晨间 review**（F3.5/F5.3） |
| **经验清零** | 项目结束知识全在个人脑子里 | 时序知识图谱记忆+跨项目检索：**经验自动沉淀复用**（F4） |
| **报价靠拍脑袋** | 售前方案制作成本高、ROI 算不清 | 售前方案+ROI 测算 10 分钟出稿（F7.2 能力复用） |

### 2.4 AI 落地团队（L2）的痛点 —— 付费主力

- **协作断层**：3 个 FDE 各干各的，方案格式不统一、经验不共享 → TE 的团队经验库/统一模板/项目看板
- **质量参差**：新人交付质量不稳，老板不敢放权 → TE 的质量标准集中管理 + 审核工作台
- **人员流动**：FDE 离职带走全部项目经验 → TE 的经验资产归属团队（组织记忆）

### 2.5 交付型公司（L3）的痛点 —— 大客单

- **交付成本高**：每个项目都要资深人力驻场 → F7 自助交付模式（客户自己用+后台赋能）是**交付公司的商业模式升级**：边际成本趋零
- **无法规模化**：人力模型决定收入天花板 → EE 多租户 SaaS 化，一个平台服务 N 个客户
- **品牌诉求**：需要白标（客户看到的是交付公司的工具）→ EE 白标

| 质量门禁+回归拦截 | ✅ | ❌ | ❌ | ⚠️ 单测层面 | ⚠️ 人工评审 | ❌ |

| 成本 | 工具费（低） | 订阅费 | 平台费 | 订阅费 | 人天费（极高） | 课程费（一次性） |
| **本质差异** | **交付生产系统** | 通用生产力 | 应用搭建平台 | 编程助手 | 人的服务 | 知识产品 |

### 3.3 独特价值定位（UVN）

> **对个人 FDE**：「从 ChatGPT 里复制粘贴的散装交付 → 一条流水线跑完的标准化交付」
> **对团队**：「新人第一天就按资深 FDE 的方法论干活，且经验沉淀在团队而非个人」
> **对交付公司**：「从卖人天 → 卖平台+赋能，客户自助、边际成本趋零」

三条护城河：
1. **方法论先发**：「验证前置+Benchmark 先行+质量门禁+日迭代」是当前开源市场空白，无同类完整工具化产品
2. **数据飞轮**：Benchmark 黄金集、行业模板库、badcase 归因经验——越用越厚，后来者难追
3. **私有化信任**：FDE 处理客户敏感文档，开源可审计+数据不出本地是天然信任壁垒（SaaS 竞品做不到）

## 4. 价值主张 → 功能映射（开发优先级的依据）

商业价值四层阶梯（按客户感知强度排序），**每一层都有对应的功能载体与可验证指标**：

| 价值层 | 客户得到的 | 功能载体 | 验证指标 | 版本落点 |
| ------ | ---------- | -------- | -------- | -------- |
| **① 省时间**（最直接） | 调研 2 周→半天；方案 1 周→1 小时初稿；周报自动生成 | F1 调研、F2 设计、F6 管控 | 交付周期实测对比 | v0.1.2（真实 LLM 打磨 B3） |
| **② 少返工**（防损失） | 验收扯皮消失、上线事故拦截、回归不倒退 | Benchmark 先行、质量门禁、夜间迭代 | 门禁拦截率、回归达标率 | v0.1.2（B1/B5） |
| **③ 多赚钱**（增长） | 并行 3-5 项目；10 分钟售前方案+ROI；复购率提升 | 全流程 AI 主导、F7.2 机会识别、经验复用 | 人均并行项目数 | v1.2-v1.3 |
| **④ 资产积累**（长期壁垒） | 个人/团队经验库、行业模板、认证体系 | F4 记忆、模板库、F8 认证 | 经验复用率 | v0.2.0 / TE |

> 开发原则：**优先做「价值可被客户当场感知」的功能**（①②层），再做粘性功能（④层为商业版蓄水）。

## 5. 开源商业模型设计（Open-Core 架构）

### 5.1 版本矩阵

| 能力 | CE 社区版（开源 MIT） | TE 团队版（订阅） | EE 企业版（私有化） |
| ---- | :---: | :---: | :---: |
| 六大 Agent + 工具层 + 评测门禁 + 迭代流水线 | ✅ | ✅ | ✅ |
| 单机 SQLite 持久化、单容器部署 | ✅ | ✅ | ✅ |
| 交付物导出（MD/DOCX）+ 基础模板包 | ✅（2 个行业包） | ✅ 全部 | ✅ 全部 |
| 本地跨项目经验记忆 | ✅ | ✅ | ✅ |
| **多用户与协作（RBAC/审核流）** | ❌ | ✅ | ✅ |
| **团队共享经验库（组织记忆）** | ❌ | ✅ | ✅ |
| **集中质量标准/模板管理** | ❌ | ✅ | ✅ |
| **多项目聚合看板/资源调度** | ❌ | ✅ | ✅ |
| **高级行业模板包**（持续更新） | ❌ | ✅ | ✅ |
| **多租户/白标/SSO/审计合规** | ❌ | ❌ | ✅ |
| **F7 自助交付 SaaS 化**（客户自助平台） | ❌ | ❌ | ✅ |
| 支持 | 社区 Issue | 工单（次日响应） | SLA（4h）+ 专属客户成功 |

**切分原则**（防社区反噬的三条红线）：
1. CE 永远完整可用——个人 FDE 用 CE 能完成真实项目交付，**不搞功能阉割式引流**
2. 商业功能围绕「组织属性」：多用户、共享、管控、合规——单机场景不碰
3. CE 与 TE 同一代码底座、同一发布节奏，TE 不藏私货（只加组织层能力）

### 5.2 代码组织与技术策略

```
cosmoxone/ai-fde-engine（开源，公开）
  ├── src/core/...          # 完整核心（Agent/工具/评测/记忆/流水线）
  └── 扩展点（关键设计）：
      ├── plugin_registry   # 插件注册器（TE 功能以插件包形式挂载）
      ├── storage_provider  # 存储抽象（CE=SQLite / TE=PostgreSQL）
      ├── auth_provider     # 认证抽象（CE=无 / TE=JWT+RBAC）
      └── template_source   # 模板源抽象（CE=内置2包 / TE=订阅源）

cosmoxone/ai-fde-engine-team（商业，私有）
  └── pip 包 ai-fde-team：安装后注入插件 → 协作/团队库/管控/PG后端
```

- 开源仓库**保持纯净可审计**，商业能力以独立包/独立仓库叠加
- `AIFDE_EDITION` 环境变量探测已安装扩展，Dashboard 动态解锁界面
- 好处：开源 CI 不受商业代码污染；商业版复用 330+ 测试底座，研发成本 ≈ 增量的 20%

## 6. 定价设计

### 6.1 定价表

| 版本 | 定价（国内） | 定价（国际） | 备注 |

增值服务线：

| 服务 | 定价 | 说明 |
| ---- | ---- | ---- |
| 行业模板包（单买） | ¥499/包/年 | 不订 TE 的 CE 用户可单买（转化漏斗中间层） |

| 企业培训 | ¥2 万/天 | 团队方法论培训 |

### 6.2 定价逻辑与锚点

- **锚点 1（人力）**：FDE 月人力成本 3-5 万；TE 席位 ¥299 = **不到 1% 取率**，只要效率提升 1% 即回本——实际省时间是 50%+
- **锚点 2（项目）**：单项目 10-50 万，多并行 1 个项目/年 = 增收 10 万+；工具年费 ¥3,588，**ROI ≈ 30 倍**
- **锚点 3（替代品）**：咨询公司做一个需求调研 5-10 万；CE 免费达到 70% 效果，TE 达到 95%
- **认证定价锚点**：市面上 AI 应用工程师培训 ¥3,000-8,000；FDE 认证带实操作品集+工具链，¥999/级 低于市场且可持续（复购三级）
- **试用策略**：TE 30 天全功能试用（不绑卡）；EE 8 周 PoC（收费 ¥3 万，可抵扣年费）

### 6.3 收入模型测算（保守，3 年）

| 时间 | 假设 | ARR |
| ---- | ---- | ---- |
| Y1 | TE 付费席位 100 + 认证 200 人 + 实施 5 单 | ≈ ¥80 万 |
| Y2 | TE 席位 400 + EE 3 家 + 认证 800 + 模板分成 | ≈ ¥450 万 |

## 7. 持续运营设计（开源商业飞轮）

```
   内容营销（交付方法论文章/案例复盘）
        │
        ▼
   CE 开源用户增长（GitHub/Discussion）
        │
        ├──→ 社区贡献（模板包 PR/badcase 经验/黄金集）──→ 数据飞轮（护城河加厚）
        │
        ▼
   免费用户中的活跃 FDE（行为数据：项目数/导出频次）
        │
        ├──→ 模板包单买（轻转化）──┐
        │                          ├──→ TE 订阅（主营收）
   团队负责人（多席位需求）────────┘
        │
        ▼
   交付公司（自助交付诉求）──→ EE 私有化 + 实施
        │
        ▼
   认证人才池 ──→ 反哺企业客户招聘 ──→ 更多企业采用（网络效应）
```

运营节奏：
- **每周**：一篇方法论内容（公众号/知乎/掘金/X），附 CE 复现步骤
- **每月**：Show your delivery 案例征集（最佳真实交付案例），优胜者模板包奖励
- **每季**：公开 Benchmark 报告（黄金集上各模型表现）——建立技术权威
- **社区分层**：Discussion（问答）→ 贡献者群（模板作者/黄金集标注员，付费激励）→ TE 客户群

资金流闭环：TE/EE/认证收入 → 养 2-3 名核心维护者 + 贡献者激励池 → 开源版本持续高频迭代 → 飞轮加速。

## 8. Roadmap 对齐（商业视角的版本意义）

| 开源版本 | 商业意义 |
| ---- | ---- |
| v0.1.1 开箱即用深化 | **转化前置条件**：装不上=留不住，SQLite 是留存底线 |
