# AI-FDE Engine 模块切换指南


> 📌 **文档状态**：已更新至 v0.2.x。LLM Key 支持在 Dashboard 设置页热配置（无需编辑 .env）；测试基数为 470。

> 从Mock模式切换到真实开源模块的完整操作手册

## 概述

AI-FDE Engine 采用「接口真实 + 实现可切换」的设计，所有模块默认使用Mock模式确保零依赖可运行。
生产环境通过修改 `.env` 配置即可切换为真实开源模块，无需修改代码。

## 模块切换总览

| 模块 | Mock模式 | 真实实现 | 配置项 | 依赖安装 |
|------|----------|----------|--------|----------|
| LLM调用 | 内置模拟 | DeepSeek V4 / Qwen3.6 | `LLM_PROVIDER` | 无需（HTTP API） |
| 文档解析 | 文本提取 | Docling / Marker v2 | `DOC_PARSER_PROVIDER` | `pip install docling` |
| 知识库 | 内存+关键词 | Qdrant + Sentence-Transformers | `KB_PROVIDER` | `pip install qdrant-client sentence-transformers` |
| 评测引擎 | 规则匹配 | DeepEval | `EVALUATION_PROVIDER` | `pip install deepeval` |
| 代码生成 | 模板脚手架 | Aider / OpenHands / OpenCode | `CODE_GEN_PROVIDER` | `pip install aider-chat` |
| 记忆系统 | JSON持久化 | Mem0 / Zep Graphiti | `MEMORY_PROVIDER` | `pip install mem0ai` |

## 1. LLM层切换（最核心，优先切换）

### 前置条件
- DeepSeek API Key 或 Qwen（通义千问）API Key
- 网络可访问对应API端点

### 切换步骤

```bash
# 编辑 .env 文件
cd deploy
vim .env

# 设置模型提供方
LLM_PROVIDER=deepseek

# 配置DeepSeek API
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxx
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
DEEPSEEK_CODE_MODEL=deepseek-v4-pro
DEEPSEEK_FAST_MODEL=deepseek-v4-flash

# 配置Qwen API（可选，用于中文调研任务）
QWEN_API_KEY=sk-xxxxxxxxxxxxxxxx
QWEN_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
QWEN_RESEARCH_MODEL=qwen3.6-27b
```

### 验证

```bash
python3 -c "
import asyncio
from src.llm import get_llm_client, LLMMessage

async def test():
    client = get_llm_client('test')
    resp = await client.chat([LLMMessage('user', '你好，请用一句话介绍自己')])
    print(f'模型: {resp.model}')
    print(f'响应: {resp.content[:100]}')
    print(f'延迟: {resp.latency_ms:.0f}ms')
    print(f'Token: {resp.usage}')

asyncio.run(test())
"
```

### 模型路由说明

系统按任务类型自动选择最优模型：
- 代码生成/方案设计 → DeepSeek V4 Pro（强推理）
- 调研分析/项目管理 → Qwen3.6（中文优化）
- 评测/快速任务 → DeepSeek V4 Flash（低成本）

可在 `.env` 中自定义：
```
MODEL_TASK_CODE=deepseek-v4-pro
MODEL_TASK_RESEARCH=qwen3.6-27b
MODEL_TASK_DESIGN=deepseek-v4-pro
```

## 2. 文档解析切换（Docling）

### 前置条件
- Python 3.10+
- 约2GB磁盘空间（模型下载）
- 可选：NVIDIA GPU（加速PDF解析）

### 切换步骤

```bash
# 安装Docling
pip install docling

# 编辑 .env
DOC_PARSER_PROVIDER=docling  # 可选: mock / docling / marker / hybrid
DOC_PARSER_LANGUAGE=chinese
DOC_PARSER_BATCH_SIZE=5
```

### 支持格式
- PDF（原生+扫描件OCR）
- DOCX / DOC
- PPTX / PPT
- HTML / XML
- 图片（PNG/JPG/TIFF）
- TXT / MD

### 验证

```bash
python3 -c "
import asyncio
from src.tools.doc_parser import DocParserTool

async def test():
    tool = DocParserTool()
    result = await tool.parse('tests/test_doc.pdf')
    print(f'成功: {result[\"success\"]}')
    print(f'页数: {result.get(\"page_count\", 0)}')
    print(f'结构化块: {len(result.get(\"structured\", []))}')
    print(f'表格: {len(result.get(\"tables\", []))}')

asyncio.run(test())
"
```

### Marker v2 备选（GPU加速）

```bash
pip install marker-pdf

# .env
DOC_PARSER_PROVIDER=marker
DOC_PARSER_MARKER_GPU=true
```

Marker v2 性能：GPU 7.4页/秒，总分76.0（超Docling 50.3），适合大批量PDF。

## 3. 知识库切换（Qdrant + 本地Embedding）

### 前置条件
- Qdrant向量数据库（Docker一键启动）
- Sentence-Transformers（首次运行下载模型约1GB）

### 切换步骤

```bash
# 1. 启动Qdrant
docker run -d -p 6333:6333 qdrant/qdrant:v1.18.3

# 2. 安装依赖
pip install qdrant-client sentence-transformers

# 3. 编辑 .env
KB_PROVIDER=qdrant  # 可选: mock / lightrag / qdrant / basic
QDRANT_HOST=localhost
QDRANT_PORT=6333
KB_EMBEDDING_MODEL=BAAI/bge-m3  # 多语言，1024维
KB_EMBEDDING_DIM=1024
KB_CHUNK_SIZE=1024
KB_CHUNK_OVERLAP=128
```

### 验证

```bash
python3 -c "
import asyncio
from src.tools.knowledge_base import KnowledgeBaseTool

async def test():
    kb = KnowledgeBaseTool('test_project')
    await kb.create('test_kb')
    await kb.add_documents('kb_test_project_test_kb', [
        {'content': '业务流程包括受理、审核、处理三个环节', 'filename': 'doc1.pdf'},
        {'content': '审核标准包括完整性和合规性', 'filename': 'doc2.pdf'},
    ])
    result = await kb.query('kb_test_project_test_kb', '业务流程有哪些？')
    print(f'检索模式: {result[\"retrieval_mode\"]}')
    print(f'结果数: {len(result[\"answers\"])}')
    for a in result['answers']:
        print(f'  分数={a[\"score\"]:.3f} 来源={a[\"source\"]}')

asyncio.run(test())
"
```

## 4. 评测引擎切换（DeepEval）

### 前置条件
- LLM API Key（DeepEval的LLM-as-judge指标需要调用LLM）
- 约500MB磁盘空间

### 切换步骤

```bash
# 安装DeepEval
pip install deepeval

# 编辑 .env
EVALUATION_PROVIDER=deepeval  # 可选: mock / deepeval
EVALUATION_GATE_ENABLED=true
EVALUATION_GATE_ACCURACY=0.8
EVALUATION_GATE_HALLUCINATION=0.1
```

### 支持的评测指标

| 指标 | 类型 | 说明 |
|------|------|------|
| HallucinationMetric | LLM-judge | 幻觉检测（基于检索上下文） |
| AnswerRelevancyMetric | LLM-judge | 答案相关性 |
| FaithfulnessMetric | LLM-judge | 忠实度（基于上下文） |
| ToxicityMetric | 模型 | 毒性检测 |
| BiasMetric | 模型 | 偏见检测 |
| 格式合规 | 规则 | 输出格式检查 |
| 安全合规 | 规则 | 敏感信息检测 |

### 验证

```bash
python3 -c "
import asyncio
from src.evaluation.evaluator import Evaluator

async def test():
    evaluator = Evaluator('test')
    result = await evaluator.evaluate_output(
        input_text='业务流程有哪些？',
        output_text='业务流程包括受理、审核、处理三个环节。',
        expected_output='业务流程包括受理、审核、处理',
        context='业务流程包括受理、审核、处理三个环节，每个环节都有明确的标准。',
    )
    print(f'通过: {result[\"passed\"]}')
    print(f'分数: {result[\"scores\"]}')

asyncio.run(test())
"
```

## 全量切换检查清单

切换到生产环境前，按以下清单逐项验证：

- [ ] **LLM层**：配置API Key，测试真实调用，验证模型路由
- [ ] **文档解析**：安装Docling，测试PDF/DOCX解析，验证结构化输出
- [ ] **知识库**：启动Qdrant，安装embedding模型，测试向量检索
- [ ] **评测引擎**：安装DeepEval，测试幻觉检测和答案相关性
- [ ] **代码生成**：安装Aider，测试项目生成，验证git工作流
- [ ] **记忆系统**：安装Mem0，测试记忆写入和语义检索
- [ ] **端到端测试**：运行 `python3 demo_e2e.py`，验证全流程
- [ ] **单元测试**：运行 `pytest tests/ -v`，确保330个测试全部通过
- [ ] **API测试**：启动服务 `uvicorn src.main:app`，访问 `/docs` 测试接口
- [ ] **性能测试**：验证各模块响应时间满足SLA
- [ ] **安全检查**：验证敏感数据脱敏、API Key安全存储

## 渐进式切换建议

不要一次性切换所有模块，建议按以下顺序逐步切换：

1. **第一阶段**：LLM层（最核心，所有Agent依赖）
2. **第二阶段**：文档解析 + 知识库（调研阶段核心）
3. **第三阶段**：评测引擎（质量保证）
4. **第四阶段**：代码生成（交付阶段）
5. **第五阶段**：记忆系统（长期优化）

每个阶段切换后，运行完整测试和端到端流程验证，确认稳定后再进入下一阶段。

## 回滚方案

任何模块切换后如出现问题，可立即回滚到Mock模式：

```bash
# 编辑 .env，将对应provider改回mock
LLM_PROVIDER=deepseek  # LLM无法回滚mock（mock无真实输出），但可切换模型
DOC_PARSER_PROVIDER=mock
KB_PROVIDER=mock
EVALUATION_PROVIDER=mock
CODE_GEN_PROVIDER=mock
MEMORY_PROVIDER=mock

# 重启服务
docker compose restart ai-fde-app
```

Mock模式下所有功能可用，仅输出质量为模拟结果，不影响流程运行。
