## 2. 过程分阶段

### 2.1 发布三件套（~10 分钟）

- **Dashboard**：单文件 HTML（972 行）纯追加两个页面——知识库（stats/检索溯源/待确认队列
  confirm+reject/重建）+ 本体图谱（抽取/stats/Mermaid 渲染 **CDN 失败自动降级源码显示**/实体软删）。
  交互全部走既有 12 个后端端点，前端零新后端代码。冒烟测试只测"服务端交付的 HTML 完整性"，
  交互逻辑由 API 测试覆盖——**前端测试分层：冒烟测结构，语义测后端**。
- **W0 补录**：会议产出（日期/对接人）用户未提供——处理方式是**用已发生的事实替代缺失的纪要**：
  W0~W3 实际全部压缩进 2026-09-17 一日闭环（转正→89/89→13/13 都有文档为证），roadmap 据实改写，
  对接人标注"已确认忽略"。教训：**补录优先写可验证事实，不编会议结论**。
- **发布整理**：版本号 0.4.0、CHANGELOG 三段 Unreleased 合并为一个版本段（含发布概要）、
  roadmap 头部发布说明 + 版本对照表。原则：**发布整理只收口不开新功能**（机制 3 明确推迟到下一轮，
  避免"顺手实现"污染发布边界）。

### 2.3 终验排障三连与执行（本轮技术含量最高的一段）

拿到 key 后按协议跑，**连续三层静默故障**，每层都是"跑完了但结果无效"：

| # | 症象 | 根因 | 解法 | 识别特征 |
|---|---|---|---|---|
| 1 | 20 条 0.1s 跑完，命中率 47.89% | 模型路由 `model_task_research` 默认 **qwen3.6-27b**，qwen 无 key → LLMClient `if not api_key` **静默返回 mock** | `MODEL_TASK_RESEARCH=deepseek-chat` 环境变量覆盖 | **耗时是探针**：真实 LLM 不可能 0.1s/条；命中率恰好等于 mock 基线 |
| 2 | 覆盖路由后仍 0.1s + mock | `src/llm/client.py` 的 `httpx.AsyncClient` 漏 `trust_env=False`，本机 socks 代理环境变量毒化，`chat_json` 内部捕获异常后**同样静默回退 mock** | 补 `trust_env=False`（一行） | 单测 `_call_llm` 通但 `parsed=None`；直接裸调 `chat_json` 才暴露真实错误 `[LLM_ERROR] ... socks://...` |
| 3 | （防患）hybrid 栏设计缺陷 | 样本文档不 ingest 进 KB → hybrid 检索空命中 → **自动回退 full** → 两栏输入完全相同，对比失真（自变量失效） | 评估器内置"先 ingest 再 execute"（每样本独立项目） | 复盘推演发现，未付出真机成本 |

修复后真实执行：full 97.18%（69/71，195s）× hybrid 98.59%（70/71，193s），40/40 真实 LLM
→ **PASS**，18 号结论生效。成本维度如实披露：黄金集样本小语料（~565 字），hybrid 反多 ~100 字/条
（符合 18 号边界规则 2 预期），大语料优势由单测覆盖（3.5 万字 reduction>0.5）。

## 3. 21 号教训的当场再犯（写给所有 Agent 的重点）

**T-4 再犯**（距 21 号成文 ~40 分钟）：新写 `test_full_mode_no_source` 时直接
`agent.settings.research_rag_mode = "full"`——`agent.settings` 是**全局单例引用**，裸赋值
泄漏到后续测试（hybrid 用例 mode_requested 变 'full' 而挂）。21 号刚写完"测试永远不动全局缓存/单例
生命周期；改配置用 monkeypatch.setattr"，转头自己犯。修复即按教训：`monkeypatch.setattr(agent.settings, ...)`。

**E1 再犯**（距首犯 ~3 小时）：E1 条目原文"任何出网客户端默认 trust_env=False"——知识库侧 8 处
httpx 全改了，`llm/client.py` 的 AsyncClient 漏网，直到终验才被 socks 代理毒化暴露。已在 21 号
E1 条目补记：**代理毒化是静默降级，必须全仓 `grep -rn "httpx\." src/` 逐一核查构造点，不能按模块记忆**。

两条再犯的共同启示：**教训文档不因"刚写完"而自动生效——同类代码点要主动扫描**（写完教训立刻
grep 全仓同类模式，是唯一可靠的预防方式）。

## 5. 经验教训（增量提炼）

1. **静默降级的三个识别探针**（终验三连的方法论沉淀）：①耗时异常（0.1s 跑完 20 条 LLM 调用不可能）
   ②结果恰好等于 mock 基线（47.89% 命中率）③逐层裸调（绕过上层包装直接调最底层，让真实错误冒头）。
   mock 兜底是可靠性的朋友、是调试的敌人——**关键评估必须验证"真实路径真的走了"**（本次靠耗时+token
   统计双重确认 40/40）。
2. **对比实验的设计前提**：跑之前推演"两栏输入是否真的不同"——hybrid 栏不先 ingest 就会静默回退，
   自变量消失，跑出的 PASS 是假 PASS。凡对比，先断言**实验组和对照组确实走了不同路径**
   （input_stats.mode_effective 就是为此设计的观测面）。
3. **发布边界纪律**：发布整理窗口拒绝新功能（机制 3 推迟），发布后跟进单独一轮——两个混合会让
   "发布"失去可审计性。
4. **负例即环境探针**：鉴权负例（401）挂了不是测试问题，是环境配置的烟雾报警器；外部依赖任何变更
   （换端口/换实例）后第一个跑的应该是负例集。
5. **终验协议先行**：golden-real 的执行协议（命令/判据/回填表）在无 key 时就写好——key 到手即一条
   命令，零犹豫零口径争议。

## 6. 最佳实践（增量清单）

**真实 LLM 评估 checklist**：
- [ ] 先验证 key（轻量 curl 一次，别拿评估套件当探针）
- [ ] 显式固定模型路由（`MODEL_TASK_*` 环境变量），不信任默认路由表
- [ ] 评估器内断言真实路径：耗时合理 + mode_effective/usage 字段核查，mock 兜底要可检测
- [ ] 对比实验先推演两栏输入差异（自变量有效性），再跑
- [ ] 成本结论按语料尺度分层披露（小语料无劣势 ≠ 无意义，如实写）

**发布收口 checklist**：
- [ ] 版本号 / CHANGELOG 合段+概要 / roadmap 头部+版本表 / 前端版本角标 四处同步
- [ ] 发布窗口不开新功能；遗留项显式列出转"发布后跟进"
- [ ] 外部依赖变更 → 鉴权负例先行 → 再跑功能集

**外部协作变更响应**：
- [ ] 对方通知"透明变更"（如地址迁移）也要全量重验——透明是对响应契约而言，部署配置不保证随迁
- [ ] 实测记录写进联调 README（含对照证据：8010 200 vs 8011 401），给对方精确修复清单
