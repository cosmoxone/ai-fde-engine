# AI-FDE Engine 后续规划（Roadmap）

> 文档版本：v2.1 | 日期：2026-09-07 | 基于：MVP v0.1.0（330 测试全绿、Mock 全流程可跑通、CI 全绿）

## 0. 项目定位（规划的出发点）

**AI-FDE Engine 是一个面向 FDE 从业者的单机开源生产力工具，不是一个企业级 SaaS 平台。**

| 核心价值 | 含义 |
| -------- | ---- |
| **单机开箱即用** | 一条命令启动（`docker run` / `pip install` + `aifde`），零外部服务依赖，数据留在本地 |
| **直接创造交付价值** | 输入客户文档 → 输出可交付物（需求基线/三方案/Benchmark/评测报告），FDE 拿来就能用 |
| **帮 FDE 省时间省精力** | 调研 3 天→半天、方案初稿自动生成、Benchmark 先行防扯皮、badcase 夜间归因 |
| **方法论独特性** | 「验证前置 + AI 主导 + 日迭代 + 记忆复用」的工具化实现，市面无同类开源项目 |

> ⚠️ 企业级特性（PostgreSQL 集群、JWT/RBAC、多租户、Argo/Celery 等）划入**商业版轨道**（§5），
> 不进入开源主线，也不阻塞开源版本演进。开源版默认面向**本机/单容器**场景。
> 商业化整体设计（用户分层/竞品/定价/运营飞轮）见 **[10-商业计划.md](10-商业计划.md)**。

## 2. 遗留问题重新分级（v0.1.0 评审遗留，按新定位归位）

### 开源主线保留项

| 编号 | 问题 | 新定位 | 处理方式 |
| ---- | ---- | ------ | -------- |
| L1-2 | 业务数据内存态，重启即丢 | 🔴 **主线 P0**（单机也要不丢数据） | 用 **SQLite 单文件持久化**解决（见 A1），不引入 PG |
| L2-1 | 夜间迭代无定时调度 | 🟠 主线 P1 | 进程内 **APScheduler** 即可（单机无需 Celery） |
| L2-3 | 性能/安全测试未正式执行 | 🟡 主线 P2 | 单机场景按需执行，验收级测试归商业版 |
| L2-4 | 真实组件联调未系统化 | 🟠 主线 P1 | 与 B 系列迭代合并（真实 LLM 打磨是核心价值） |
| L2-5 | 用户手册缺失 | 🟠 主线 P1 | 开箱即用的重要组成部分 |
| L3-2 | 覆盖率报告未沉淀 | 🟢 主线 P3 | CI 加 Codecov |
| L3-5 | 英文 README 缺失 | 🟡 主线 P2（进入 C 系列迭代） | 国际分发需要 |
| L3-3 | 全量镜像体积大 | 🟡 主线 P2 | profile 化构建（mock/standard/full） |

### 移入商业版轨道（不阻塞开源演进）

| 编号 | 原问题 | 归位说明 |
| ---- | ------ | -------- |
| L1-1 | JWT 认证 + RBAC | 企业多用户场景；开源版定位本机使用，操作系统级隔离即可 |
| L1-3 | 多租户数据隔离 | SaaS 化前提，纯商业特性 |
| L2-2 | WebSocket 实时推送 | Dashboard 轮询在单机场景够用；体验增强归商业版 |
| L2-6 | alembic 迁移工程 | 随 SQLite 方案以轻量方式解决（建表 SQL 即可），完整迁移体系归商业版 |
| L3-1 | pydantic-ai 依赖声明 | 保持现状（README 已澄清），迁移与否由主线演进自然决定 |

## 3. 开源主线迭代（三个版本，约 6-9 周）

### A. v0.1.1 开箱即用深化 — 约 2 周

**目标：装上就能干活，关掉数据不丢**

| # | 任务 | 说明 | 验收 |
| - | ---- | ---- | ---- |
| A1 | **SQLite 单文件持久化** | 标准库 sqlite3，`data/aifde.db`；替换内存 dict（保留 `storage_provider=memory` 供测试）；记忆 JSON 与 DB 统一到 `data/` 目录 | 重启后项目/任务/审核队列/Benchmark 全部保留；330 测试不破坏 |
| A2 | **单容器模式** | `docker run -p 8000:8000 -v aifde-data:/app/data cosmoxone/ai-fde-engine` 即全功能（Mock）；Compose 六服务降级为可选 `docker-compose.full.yml` | 单容器健康检查通过 + 数据卷持久化 |
| A3 | **首次启动引导** | 无 API Key 时 Dashboard 顶部提示条 + 设置页直接填 Key（写 .env 并热生效），无需手动编辑文件 | 浏览器内完成 DeepSeek/Qwen Key 配置并真实调用成功 |
| A4 | 快速体验打磨 | `examples/run_demo.sh` 输出交付物到 `output/` 目录；README 补 3 分钟 GIF/截图 | 新用户 3 分钟内看到第一份 AI 生成的需求基线 |
| A5 | **商业扩展点预留**（为 TE 铺路，不实现商业功能） | 抽象三个接口位：`storage_provider`（CE=SQLite/TE=PG）、`auth_provider`（CE=无/TE=JWT+RBAC）、`plugin_registry`（TE 功能以插件包挂载）；开源版只带默认实现 | 扩展点有单测覆盖；第三方可按接口实现自定义存储 |

### B. v0.1.2 交付价值放大 — 约 3 周（核心竞争力）

**目标：输出物达到「直接给客户看」的水平**

| # | 任务 | 说明 | 验收 |
| - | ---- | ---- | ---- |
| B1 | **交付物导出** | 需求基线/产品·技术·验证三方案/Benchmark 测试集/评测报告 → 导出 Markdown + **DOCX**（python-docx，零重依赖）；项目一键打包 zip | 导出的需求文档含功能清单+量化验收标准，Word 可直接编辑 |
| B2 | **行业模板库（独特性）** | 内置 2-3 个行业包（制造业质检/金融客服/政务问答）：需求模板+方案骨架+Benchmark 样例；调研 Agent 按行业注入上下文 | 同样的输入文档，带行业模板的输出质量显著优于无模板 |
| B3 | **真实 LLM 输出打磨** | DeepSeek/Qwen 下逐 Agent 优化 Prompt（结构化指令+few-shot+输出 schema 校验重试）；建立 20 条人工评分黄金集做回归 | 黄金集上需求基线可用率 ≥80%（FDE 人工评定） |
| B4 | **可编辑确认流** | Dashboard 上直接修改 AI 生成的需求项/方案段落再确认（当前只有整体确认） | 修改后的内容进入基线并导出 |
| B5 | **Badcase 实用闭环** | CLI/网页 10 秒提交 badcase；夜间迭代输出「修复建议 diff」（Prompt 补丁/知识库补充清单）供 FDE 采纳，而非全自动改 | 早上 review：每条 badcase 有明确归因+建议动作 |
| B6 | 用户手册（FDE 视角） | 按角色场景写操作手册，放 docs/ | 新 FDE 按手册 30 分钟跑通首个项目 |

## 5. 商业版轨道（独立演进，不阻塞开源）

> 商业化完整设计（用户分层/竞品分析/价值定位/定价表/运营飞轮/收入测算）见 **[10-商业计划.md](10-商业计划.md)**，本节仅列工程要点。

### 5.1 产品分层

| 版本 | 定位 | 定价 | 核心能力 |
| ---- | ---- | ---- | ---- |
| **CE 社区版**（本仓库） | 单机 FDE 生产力工具 | 免费（MIT） | 全核心功能，完整可用，2 个行业模板包 |
| **TE 团队版**（私有仓库） | AI 落地团队协作平台 | ¥299/人/月 起 | 多用户 RBAC、团队经验库、PG 后端、集中质量标准/模板、聚合看板、工单支持 |
| **EE 企业版**（私有仓库） | 交付公司自助交付平台 | ¥15 万/年起 | 多租户、白标、SSO/审计、F7 自助交付 SaaS 化、SLA |

**三条红线**（防社区反噬）：
1. CE 永远完整可用——个人 FDE 用 CE 能完成真实项目交付，不搞功能阉割
2. 商业功能只做「组织属性」（多用户/共享/管控/合规），单机场景不碰
3. CE/TE 同底座同节奏，TE 不藏核心功能

### 5.2 技术架构（开源仓库保持纯净）

- 开源仓库内置**扩展点**（v0.1.1 A5 预留）：`storage_provider` / `auth_provider` / `plugin_registry` / `template_source` 接口 + CE 默认实现
- 商业功能以独立 pip 包（`ai-fde-team`）/ 私有仓库形式叠加，安装即注入插件，`AIFDE_EDITION` 探测解锁
- 商业版复用开源 330+ 测试底座与 CI 流水线，研发增量 ≈ 20%

### 5.3 原 L 系列遗留问题归位（不变）

L1-1 JWT/RBAC、L1-3 多租户、L2-2 WebSocket、完整 alembic/PG 体系 → 全部由 TE/EE 承载，开源版不实现。

## 6. 追踪方式

- 每个迭代建 GitHub Milestone（v0.1.1 / v0.1.2 / v0.1.3）
- 上表 A/B/C/D 编号直接作为 Issue 标题前缀（如 `B1 交付物导出DOCX`）
- PR 描述关联本文档编号，保持文档-代码-测试三者同步（继承 F 编号追踪矩阵机制）
