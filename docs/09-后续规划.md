## 0. 定位（规划的出发点）

**单机开箱即用的开源 FDE 交付引擎**：输入客户文档 → 输出可交付、可验收、可复用的 AI 落地项目。企业级特性（多用户/PG/多租户）在商业轨道（[10-商业计划](10-商业计划.md)），不阻塞开源主线。

## 2. 版本规划

### v0.4.0「知识与本体」——当前迭代（设计见 [13-本体与知识库深化设计](13-本体与知识库深化设计.md) v1.1；接口契约 [14-知识库接口规格](14-知识库接口规格.md) **v1.2**）

> 架构原则：**知识库为独立模块接入**——协作方 **kb-os**（联合方案已定稿：[15-评审回复](15-对接方案评审回复.md) × kb-os《09-ai-fde对接方案》v1.1 §七 共识）；
> 三决策：**文档级推送**（切块主权归知识库侧）/ **Scoped API Key 即项目身份** / **走法 A**（我方 `KbOsGateway` 适配器消费 kb-os 原生 API）；
> 本项目 = 用户界面 + 前期处理（元数据预标注）+ 交互处理 + 编排消费；Embedded 参考实现补文档级语义（内嵌切块器）。

| 步 | 内容 | 验收 |
| --- | --- | --- |
| **a. 契约与接入层** | `src/knowledge/`：KnowledgeGateway 抽象 + Embedded 参考实现（SQLite FTS5 + **内嵌切块器，文档级语义**）+ **KbOsGateway 适配器**（按 09 方案 §4.4 映射）+ 文档级自动 ingest 管线 + Dashboard 待确认队列（页码分页） | 契约测试（`tests/contract/` 场景内核+双适配）双实现通过；零依赖上传→检索闭环；pending→confirm 交互闭环 |
| **b. 本体抽取** | `src/ontology/`：LLM 增量抽取（实体/关系/规则）+ merge + 本体 API + Mermaid 图 | ✅ 2026-09-17 v0.4-b 交付：多文档实体 24+/关系 18+（Mock 验收）；增量不重复计数（merge 幂等）；**对外独立服务契约 [20 号](20-本体服务接口规格.md) v0.1-draft**（Embedded/Remote/Fallback 同构，独立组件融合入口 `/hints`）；entity_hints 已回填 ingest 管线 |

| **协作项（已排期）** | kb-os：W1 交付 documents/stats/溯源五字段/error_key + 发联调 key；W2 entries 生命周期。我方：W1 并行 KbOsGateway（~1 人日）；W3 契约测试对拍 | ✅ **全部提前至 2026-09-17 一日内闭环**（原 W0~W3 排期压缩）：W0 会议转正 v1.2 → kb-os W1/W2 代码交付（[16 号回执](16-14号v1.2过目确认-kb-os.md) 89/89）→ W3 真机对拍 **13/13**（[19 号回执](19-W3对拍结果回执-ai-fde.md)）。双方对接人名单待补（不阻塞，协作已收口） |
