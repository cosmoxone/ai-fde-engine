## 3. P2 生产化路线（三个迭代，建议 6-8 周）

### 迭代一：数据持久化 + 认证（安全底座）— 约 2.5 周

**目标：可多副本部署、API 不裸奔**

1. **PostgreSQL 持久化**
   - 落地技术方案 §3.2 的 9 张表 DDL（projects/documents/requirements/benchmarks/test_cases/versions/evaluation_results/badcases/tasks）
   - SQLAlchemy 2.0 模型 + alembic 迁移工程（解决 L2-6）
   - 内存 dict → Repository 层替换，保留内存实现作为 `storage_provider=memory`（测试/演示用，330 个测试不破坏）
   - 对象存储：文档原文从 `/tmp` → MinIO（compose 已就绪）
   - **验收**：重启服务数据不丢；`make db-migrate` 可用；测试全绿

2. **JWT 认证 + RBAC**
   - 实现需求 §4.3.2 权限矩阵（admin/fde/manager/client 四角色）
   - FastAPI 依赖注入鉴权；首次启动自动创建管理员（`.env` 的 ADMIN_* 已有）
   - 操作审计日志中间件（谁/何时/做了什么），满足 §4.3.1 保留 180 天
   - 敏感信息脱敏过滤器（Capability 钩子位已预留）
   - **验收**：无 Token 401、越权 403；安全测试用例（L2-3 部分）通过

### 迭代二：调度与实时能力 — 约 2 周

**目标：夜间迭代真正无人值守**

1. **定时调度**（L2-1）
   - 首选 APScheduler（单体）→ Celery Beat + Redis（compose 已含 Redis）按并发需求升级
   - 定时任务：夜间迭代（20:00）、记忆巩固（03:00，cron 配置已存在）
2. **WebSocket 推送**（L2-2）
   - 5 类事件：task.progress / agent.output / evaluation.complete / iteration.complete / risk.alert
   - Dashboard 从轮询切换推送
   - **验收**：夜间迭代定时自动触发并完成；Dashboard 实时刷新

### 迭代三：真实组件联调与验收闭环 — 约 2-3 周

**目标：产出真实环境验收报告**

1. **真实组件全链路联调**（L2-4）：DeepSeek/Qwen + Docling + Qdrant + DeepEval + Aider + Mem0，用 `switch_modules.py verify --all` 逐项出报告
2. **性能测试执行**（L2-3）：验证方案 §5 十项指标实测（文档解析速度/知识库构建/Benchmark 跑批/API P95 等），回填追踪矩阵
3. **安全测试执行**（L2-3）：传输/存储加密、脱敏、注入、越权、沙箱隔离
4. **AI 专项评测**（验证方案 §4）：需求基线准确率 ≥80%、代码可运行率 ≥70% 等验收指标实测
5. **用户手册 + 运维手册**（L2-5），发布 v1.1.0
   - **验收**：验证方案 §8 验收标准全项通过，出验收报告

## 4. 远期方向（v2.x，探索性）
