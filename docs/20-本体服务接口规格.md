# 本体服务接口规格（Ontology Service API Spec）

> 版本：**v0.1-draft** | 日期：2026-09-17 | 状态：**参考实现已交付（v0.4-b），对外承诺前为 draft**
> 设计源：[13-本体与知识库深化设计](13-本体与知识库深化设计.md) §3.2（"本体留本项目"，业务建模层）
> 用途：AI-FDE Engine 本体能力的**对外独立服务接口**——本体可独立部署为服务，供主引擎
> Remote 消费（`ONTOLOGY_SERVICE_URL`），或供**其他独立组件**（前期处理/第三方编排）直接 HTTP 融合。
> 风格对齐知识库契约 [14 号](14-知识库接口规格.md) v1.2（错误码字符串码、参考实现即规格、
> 最终一致演进路径）；当前已知实现：**EmbeddedOntologyGateway**（本仓库 v0.4-b，SQLite）。

---

## 1. 总则

- **传输**：HTTP/1.1+，JSON（UTF-8）。基准地址 `ONTOLOGY_SERVICE_URL`（如 `http://onto:8020`）。
- **鉴权（v0.1）**：静态 Bearer token（`ONTOLOGY_SERVICE_TOKEN`，未配置则放行——单机演示形态）。
  `/health` 不鉴权。多租户演进路径：独立部署侧换 scoped key（对齐 14 号 v1.2 §1，届时升 v1.0）。
- **项目上下文**：`X-Onto-Project` 头（缺省 `default`）——单 token/多项目演示形态。
- **幂等性（merge 语义）**：
  - 实体按 `(project, type, name)` 归一化哈希幂等——重复抽取**属性合并**（新键补充、
    `source_docs` 追加去重、confidence 取 max），**图规模不重复增长**；
  - 关系按 `(project, from, to, relation_type)` 幂等；规则按 `(condition, conclusion)` 哈希幂等；
  - 孤儿关系（端点实体不存在）不入库，计入 `skipped_orphan_relations`；
  - **人工删除为软删且不被后续 upsert 复活**（`skipped_deleted_entities`，13 号 §五 风险表）。
- **抽取模式**：服务端自选——LLM 结构化抽取（有 Key）或行业模板 Mock（无 Key），响应 `mode`
  字段透出（`llm` / `mock` / `mock-fallback`）。消费方不得依赖 mode 值分支业务逻辑。
- **错误格式**：非 2xx 返回 `{"error": {"code": str, "message": str}}`；`code` 为稳定字符串码（§4）。

## 2. 端点优先级

| 优先级 | 端点 | 说明 |
| --- | --- | --- |
| **P0** | `POST /extract` | 单文档抽取 + 增量 merge（主入口） |
| **P0** | `GET /graph` | 本体图（节点/边/规则/统计） |
| **P0** | `GET /summary` | 本体压缩摘要（`business_model_summary`，research prompt 注入用） |
| **P1** | `GET /mermaid` | Mermaid 文本（Dashboard 直染） |
| **P1** | `GET /entities?q=` | 实体检索（含已删除过滤） |
| **P1** | `DELETE /entities/{id}` | 人工删除（软删；Dashboard 幻觉实体处置） |
| **P1** | `POST /hints` | entity_hints 预标注（**独立组件融合入口**：前期处理为知识库 ingest 打标） |
| **P2（增强）** | `GET /stats`、批量删除、本体导出/导入（OWL/JSON-LD）、scoped key | 按需协商 |

## 3. 端点详情

### 3.1 `POST /extract`

请求：`{"title": str, "content": str(必填,≤1MB), "doc_ref": str, "industry": str}`
响应 200（MergeReport）：

```json
{"doc_ref": "doc-42", "entities_added": 21, "entities_merged": 3,
 "relations_added": 18, "rules_added": 4,
 "skipped_orphan_relations": 0, "skipped_deleted_entities": 0, "mode": "llm"}
```

错误：`content` 空 → 400 `invalid_request`；超 1MB → 413 `payload_too_large`。
**同步抽取**（单文档单次 LLM 调用）；批量增量由消费方循环或引擎侧 `POST /ontology/extract` 任务化（按 doc_ref 记账跳过已抽取）。

### 3.2 `GET /graph`

响应：`{"project_id", "entities": [Entity], "relations": [Relation], "rules": [Rule], "stats": {"entities", "relations", "rules", "entity_types": {类型: 数}}}`。
已软删实体不出现在 entities，其关联关系同步过滤。

### 3.3 `GET /summary` / `GET /mermaid`

summary：`{"summary": "…markdown 压缩摘要…"}`（空本体返回提示文案）。
mermaid：`text/plain`，`graph LR` + 实体节点（`名称<br/>类型`）+ 关系边（`-->|"关系"|`）；
超 200 实体截断保护（尾注说明）。

### 3.4 `GET /entities?q=&limit=`

q 匹配实体名/类型（包含、大小写不敏感；空 q 全量）；响应 `{"entities": [Entity], "total": n}`。

### 3.5 `DELETE /entities/{id}`

响应 `{"deleted": true, "id"}`；不存在或已删 → 404 `not_found`。软删幂等。

### 3.6 `POST /hints`（独立组件融合入口）

请求：`{"title": str, "content": str}` → 响应 `{"hints": ["来料检验IQC", …]}`
语义：active 实体名/别名在文本中出现即命中（上限 20）。用途：前期处理组件为知识库
ingest metadata 生成 `entity_hints`（契约 14 号 §3.1"存而不滤"，本体过滤 P2 预留）。

## 4. 错误码表

| HTTP | code | 场景 |
| --- | --- | --- |
| 400 | `invalid_request` | 请求体缺字段/类型错误 |
| 401 | `unauthorized` | Bearer 缺失/不匹配（token 已配置时） |
| 404 | `not_found` | 实体不存在或已删除 |
| 413 | `payload_too_large` | content 超 1MB |
| 500 | `internal_error` | 服务内部错误 |

## 5. 数据模型（DTO）

- **Entity**：`{id(稳定哈希), type, name, properties: {}, confidence, source_docs: [], first_seen, last_seen}`
  —— type 建议词表：流程节点/数据资产/系统/角色/物料/合规要求/项目/其他
- **Relation**：`{from_entity(id), to_entity(id), relation_type, source_docs}`——建议：属于/触发/产生/依赖/消费/约束
- **Rule**：`{id, condition, conclusion, confidence, source_docs}`（IF condition THEN conclusion，含合规红线）

## 6. 参考实现与独立部署

- **EmbeddedOntologyGateway 即规格**（"参考实现即规格"，对齐 14 号 §7 原则）：SQLite
  （`onto_entities`/`onto_relations`/`onto_rules`/`onto_extracted_docs`），增量 merge 幂等。
- 独立部署：`uvicorn src.ontology.server:app --port 8020`（`ONTOLOGY_SERVICE_TOKEN` 可选）。
- 消费方式三态（同构 Gateway 抽象）：
  1. 进程内 Embedded（默认，`ONTOLOGY_DB_PATH`）；
  2. 主引擎 Remote：配置 `ONTOLOGY_SERVICE_URL` 即启用（Fallback 网关：远端故障自动降级
     Embedded 并标记 `degraded_since`；契约错误不降级）；
  3. 第三方组件直接 HTTP（本规格即契约面）。
- 引擎侧等价端点：`/api/v1/projects/{id}/ontology[/extract|/mermaid|/summary|/entities…]`
  （项目路由内嵌，v0.4-b 已交付）。
