## 1. 项目背景与目标

### 1.1 背景
FDE（Forward Deployed Engineer，前沿部署工程师）是AI落地的最后一公里角色。当前FDE交付存在三大痛点：
- **需求模糊**：客户诉求不清晰，验收标准后置，导致项目扯皮
- **效率低下**：手工作坊式交付，单个FDE同时只能承载1-2个项目
- **经验难复用**：每个项目从零开始，踩过的坑无法沉淀复用

### 1.2 目标
构建一套**AI驱动的FDE交付引擎**，实现：
- 交付周期从4-8周压缩到10天
- 人工工作量减少70%
- 单个FDE并行承载3-5个项目
- 项目经验自动沉淀，跨项目复用

### 1.3 核心设计原则
- **验证前置**：先做Benchmark、先定验收标准，再开发
- **AI主导、人做决策**：80%重复性工作AI自动执行，人只在关键节点审核
- **日迭代闭环**：白天收数据，夜间自动修复迭代
- **记忆驱动**：项目经验自动沉淀到时序知识图谱，跨项目复用

## 2. 用户角色与使用场景

### 2.1 角色体系总览

AI-FDE Engine 采用**"三核心+一支撑"**的角色体系，覆盖从商业拓展到项目交付再到客户自助的完整价值链：

```
┌─────────────────────────────────────────────────────────────┐
│                    AI落地合伙人（商业层）                      │
│          多项目管控 · 质量把控 · 商业拓展 · 资源调度           │
└──────────────────────┬──────────────────────────────────────┘
                       │ 分配项目 / 审核交付 / 赋能培训
┌──────────────────────▼──────────────────────────────────────┐
│                    FDE工程师（交付层）                         │
│        项目交付主力 · AI输出审核 · 关键决策 · 客户沟通         │
└──────────────────────┬──────────────────────────────────────┘
                       │ 后台Review / 培训纠偏 / 价值保障
┌──────────────────────▼──────────────────────────────────────┐
│                    自助型客户（使用层）                        │
│       自主完成AI落地 · Agent引导 · 后台赋能 · 价值共创         │
└─────────────────────────────────────────────────────────────┘
                       ▲
                       │ 基础设施运维 / 模型管理 / 安全审计
┌──────────────────────┴──────────────────────────────────────┐
│                    系统管理员（支撑层）                        │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 核心角色一：AI落地合伙人

#### 2.2.1 角色定位
AI落地合伙人是系统的**商业决策者和质量把控者**，负责将AI-FDE Engine作为核心生产工具，规模化拓展AI落地业务，同时把控所有项目的交付质量和商业价值。

典型画像：
- 公司合伙人 / 业务负责人 / AI落地团队负责人
- 同时管理5-20个AI落地项目
- 对AI技术有深度理解，同时具备商业敏感度
- 核心KPI：项目成功率、客户满意度、人效比、复购率

#### 2.2.2 核心职责
| 职责域 | 具体职责 |
|--------|----------|
| **商业拓展** | 利用系统快速生成项目方案和ROI测算，支撑售前沟通；基于历史项目数据优化报价策略 |
| **多项目管控** | 全局看板查看所有项目进度、健康度、风险；资源调度和优先级调整 |
| **质量把控** | 抽查项目交付物质量；审核关键节点（需求基线、方案、上线）；定义和迭代质量标准 |
| **团队赋能** | 基于系统沉淀的最佳实践培训FDE团队；建立项目复盘机制；优化交付方法论 |
| **客户关系** | 重点客户的高层沟通；项目价值汇报；续约和增购机会识别 |
| **资产沉淀** | 推动项目经验转化为可复用资产；维护行业解决方案库；管理知识产权 |

#### 2.2.3 核心使用场景
1. **晨会巡检**：打开全局看板，5分钟内了解所有项目健康度，识别风险项目并介入
2. **售前支持**：输入客户行业和痛点，10分钟内生成定制化方案和ROI测算，用于客户沟通
3. **质量抽查**：随机抽取项目的需求基线/方案/评测报告，审核质量，发现问题及时纠偏
4. **月度复盘**：查看月度项目数据（成功率、平均交付周期、人效、客户满意度），优化运营策略
5. **团队培训**：基于系统沉淀的最佳实践案例，组织FDE团队培训和方法论迭代

#### 2.2.4 系统功能权限
- ✅ 全部项目的查看和管理权限
- ✅ 全局数据看板和报表
- ✅ 质量标准定义和迭代
- ✅ 最佳实践库管理
- ✅ FDE团队成员管理和权限分配
- ✅ 系统级配置（模型选型、阈值调整）
- ❌ 不直接参与具体项目的日常交付操作（可查看和审核，但执行由FDE负责）

#### 2.2.5 与系统的交互方式
- **全局看板**：Web端仪表盘，多项目聚合视图
- **审核工作台**：关键节点待审核列表，一键通过/驳回/批注
- **报表中心**：自动生成的周报/月报/季度复盘报告
- **移动端**：关键风险预警推送，移动端审批

### 2.3 核心角色二：FDE工程师

#### 2.3.1 角色定位
FDE工程师是系统的**交付执行者和AI协作者**，利用AI-FDE Engine将交付周期从4-8周压缩到10天，同时从"手工作坊式交付"升级为"AI主导、人做决策"的高效交付模式。

典型画像：
- 前沿部署工程师 / AI解决方案工程师 / 全栈工程师
- 同时并行3-5个项目
- 具备AI技术理解能力 + 业务沟通能力 + 工程落地能力
- 核心KPI：项目交付质量、交付周期、客户满意度、AI输出采纳率

#### 2.3.2 核心职责
| 职责域 | 具体职责 |
|--------|----------|
| **项目启动** | 创建项目、上传客户业务资料、填写客户需求、触发AI调研分析 |
| **需求分析** | 审核AI生成的业务流程建模、数据资产梳理、需求规格；与客户确认需求基线 |
| **方案设计** | 审核AI生成的产品/技术/验证方案；调整技术选型；确认方案后进入开发 |
| **开发交付** | 监督AI代码生成；审核代码质量；部署测试环境；协调客户验收 |
| **迭代优化** | 收集Badcase；审核夜间自动迭代结果；确认版本上线或回滚 |
| **客户沟通** | 日常客户对接；进度汇报；问题解答；培训客户使用系统 |
| **经验沉淀** | 项目结束后填写复盘；标记可复用资产；贡献最佳实践 |

#### 2.3.3 核心使用场景
1. **新项目启动（Day 1-3）**：上传客户资料→AI自动调研→审核需求基线→与客户确认
2. **方案设计（Day 3-5）**：AI生成三方案→审核调整→客户确认→进入开发
3. **快速迭代（Day 6-10）**：白天收集Badcase→夜间AI自动修复→早上审核版本→部署上线
4. **客户培训**：引导客户使用自助工作台；解答客户问题；纠偏客户操作
5. **项目复盘**：项目结束后AI自动生成复盘报告→审核补充→沉淀到知识库

#### 2.3.4 系统功能权限
- ✅ 所负责项目的全部操作权限
- ✅ AI输出的审核、修改、确认权限
- ✅ 项目配置（Benchmark阈值、质量门禁调整）
- ✅ 客户账号创建和权限管理
- ✅ 查看历史项目经验和最佳实践
- ❌ 无法查看非负责项目的详细数据（合伙人授权除外）
- ❌ 无法修改系统级配置和质量标准

#### 2.3.5 与系统的交互方式
- **项目工作台**：单项目全流程操作界面，阶段式引导
- **审核界面**：AI输出逐行审核，支持修改、批注、确认
- **对话式交互**：与Agent自然语言对话，调整方案、生成代码、分析问题
- **IDE集成**：代码生成结果直接在IDE中查看和修改
- **移动端**：客户消息推送、紧急审批

### 2.4 核心角色三：自助型客户

#### 2.4.1 角色定位
自助型客户是系统的**使用者和价值共创者**，通过AI Agent引导，自主完成AI落地的全过程（从需求梳理到方案设计到试用验证），后台由FDE工程师实时Review和赋能，确保过程产生真实业务价值。

这是AI-FDE Engine的**商业模式创新**：从"我们帮客户做"升级为"客户自己做，我们后台赋能"，大幅降低交付成本，同时提升客户参与感和价值感知。

典型画像：
- 客户方的业务负责人 / IT负责人 / 数字化转型负责人
- 对AI有兴趣但缺乏专业能力
- 希望低成本、低风险地探索AI落地
- 核心诉求：快速看到AI落地效果、掌握AI落地方法论、培养内部AI能力

#### 2.4.2 核心职责
| 职责域 | 具体职责 |
|--------|----------|
| **自主探索** | 在Agent引导下完成业务梳理、需求分析、方案设计 |
| **资料提供** | 上传业务文档、描述业务痛点、回答Agent的澄清问题 |
| **试用验证** | 试用AI生成的原型/知识库/问答系统，反馈使用体验 |
| **决策确认** | 确认需求基线、选择方案、决定是否进入开发 |
| **内部推广** | 将AI落地成果在内部推广，收集内部用户反馈 |
| **能力建设** | 通过系统学习AI落地方法论，培养内部AI能力 |

#### 2.4.3 核心使用场景
1. **AI落地启蒙（第1周）**：Agent引导客户梳理业务痛点→识别AI落地机会→生成ROI测算→客户决定是否深入
2. **需求自主梳理（第2周）**：客户上传业务资料→Agent自动分析→客户审核调整→生成需求基线
3. **方案自助设计（第3周）**：Agent生成产品/技术方案→客户选择配置→生成可试用的原型
4. **原型试用验证（第4周）**：客户试用知识库问答/智能助手→收集反馈→Agent自动优化
5. **价值确认与决策（第5周）**：查看价值报告→决定是否付费进入正式开发→或继续自助迭代

#### 2.4.4 后台赋能机制（关键创新）

自助型客户不是"无人管"的，而是有**三层后台赋能**确保价值产出：

| 赋能层 | 触发时机 | 赋能方式 | 负责人 |
|--------|----------|----------|--------|
| **实时Review** | 客户每完成一个关键节点 | FDE工程师后台审核客户操作和AI输出，发现问题即时介入 | FDE工程师 |
| **主动纠偏** | 客户操作偏离最佳实践/需求理解错误 | Agent自动提示 + FDE工程师主动联系客户，纠正方向 | FDE工程师 + Agent |
| **培训赋能** | 客户首次使用某功能/遇到重复问题 | 系统自动推送教程 + FDE工程师组织培训，提升客户AI能力 | FDE工程师 + 系统 |

#### 2.4.5 系统功能权限
- ✅ 所关联项目的查看和操作权限（限于自助阶段）
- ✅ Agent引导式交互（非专业用户友好）
- ✅ 原型试用和反馈提交
- ✅ 查看项目进度和价值报告
- ✅ 查看AI落地教程和最佳实践
- ❌ 无法查看其他客户项目数据
- ❌ 无法修改系统级配置
- ❌ 无法直接执行生产环境部署（需FDE审核确认）
- ❌ 自助阶段无法访问完整代码生成功能（付费后解锁）

#### 2.4.6 与系统的交互方式
- **引导式工作台**：步骤化引导，每步有说明和示例，降低使用门槛
- **对话式Agent**：自然语言交互，客户用业务语言描述需求，Agent自动转化为技术方案
- **原型预览**：AI生成的知识库/问答系统可直接在浏览器中试用
- **价值仪表盘**：可视化展示AI落地带来的效率提升、成本节约、质量改善
- **帮助中心**：内置AI落地教程、常见问题、最佳实践案例
- **即时沟通**：内置与FDE工程师的沟通通道，问题即时响应

## 3. 功能需求

#### 3.7.1 自助交付流程（5周模型）

```
第1周：AI落地启蒙
  ├── Agent对话引导 → 梳理业务痛点
  ├── AI机会识别 → 生成3-5个落地方向
  ├── ROI测算 → 每个方向的投入产出比
  └── 客户决策 → 选择1-2个方向深入

第2周：需求自主梳理
  ├── 客户上传业务资料
  ├── Agent自动分析 → 生成需求初稿
  ├── 客户确认/修改/补充
  ├── 后台FDE Review → 纠偏和补充
  └── 输出：可验证需求基线

第3周：方案自助设计
  ├── 方案配置向导 → 选择功能模块
  ├── Agent生成技术方案和成本估算
  ├── 原型即时生成 → 可试用版本
  ├── 客户试用和反馈
  └── 输出：确认方案 + 可试用原型

第4周：原型试用验证
  ├── 客户深度试用原型
  ├── 自动收集使用数据和Badcase
  ├── Agent夜间自动优化迭代
  ├── FDE后台Review和赋能
  └── 输出：优化后原型 + 试用报告

第5周：价值确认与决策
  ├── 价值仪表盘 → 展示量化收益
  ├── 客户内部汇报材料自动生成
  ├── 正式开发方案和报价生成
  ├── 客户决策：付费开发 / 继续自助迭代 / 终止
  └── 输出：决策结果 + 下一步行动计划
```

```
  └── 考核：独立完成开发交付并通过质量门禁

第5周：客户沟通与项目管理（L3）
  ├── 模拟客户沟通：AI扮演客户，演练需求确认/方案汇报/异议处理

  └── 考核：独立完成一次客户方案汇报

  ├── 综合沙箱项目：独立完成完整项目交付（调研→方案→开发→迭代→验收）
  ├── AI教练全程评估，记录每个环节的表现

```

## 4. 非功能需求

### 4.1 性能要求
- 文档解析：GPU环境下≥5页/秒，CPU环境下≥1页/秒
- 知识库构建：100页文档≤10分钟完成图谱构建
- Benchmark跑批：100条测试用例≤5分钟完成
- API响应：简单查询≤2秒，复杂推理≤30秒

### 4.2 可用性要求
- 系统可用性≥99.5%（MVP阶段）
- 支持Docker一键部署，30分钟内完成环境搭建
- 支持私有化部署，数据不出客户环境

### 4.3 安全要求

#### 4.3.1 基础安全
- 客户数据加密存储（AES-256），传输加密（TLS 1.3）
- 代码Agent运行在沙箱环境，禁止直接访问生产系统
- 所有操作审计日志可追溯，保留期≥180天
- 敏感信息（API Key、密码、手机号）自动脱敏展示

#### 4.3.2 基于角色的访问控制（RBAC）

系统采用**四级角色权限模型**，每个角色拥有明确的功能权限和数据权限：

| 功能模块 | AI落地合伙人 | FDE工程师 | 自助型客户 | 系统管理员 |
|----------|:----------:|:---------:|:---------:|:---------:|
| **全局看板** | ✅ 全部项目 | ✅ 所负责项目 | ❌ | ✅ 系统状态 |
| **项目创建** | ✅ 无限制 | ✅ 所负责项目 | ✅ 自助项目（受限） | ❌ |
| **调研分析** | ✅ 查看审核 | ✅ 操作审核 | ✅ 自助引导 | ❌ |
| **方案设计** | ✅ 查看审核 | ✅ 操作审核 | ✅ 自助配置（受限） | ❌ |
| **代码生成** | ✅ 查看 | ✅ 操作审核 | ❌（付费后解锁） | ❌ |
| **生产部署** | ✅ 审批 | ✅ 操作 | ❌ | ✅ 运维 |
| **Benchmark评测** | ✅ 查看 | ✅ 操作 | ✅ 查看结果 | ❌ |
| **夜间迭代** | ✅ 查看 | ✅ 操作审核 | ❌ | ❌ |
| **记忆系统** | ✅ 全部项目 | ✅ 所负责项目 | ✅ 本项目 | ❌ |
| **后台Review** | ✅ 抽查 | ✅ 所负责客户 | ❌ | ❌ |
| **培训赋能** | ✅ 管理 | ✅ 执行 | ✅ 接收 | ❌ |
| **价值仪表盘** | ✅ 全部项目 | ✅ 所负责项目 | ✅ 本项目 | ❌ |
| **用户管理** | ✅ FDE/客户账号 | ✅ 客户账号 | ❌ | ✅ 全部账号 |
| **系统配置** | ✅ 业务配置 | ❌ | ❌ | ✅ 全部配置 |
| **质量标准** | ✅ 定义迭代 | ✅ 执行 | ❌ | ❌ |
| **审计日志** | ✅ 业务审计 | ✅ 所负责项目 | ❌ | ✅ 全部审计 |

**数据权限规则：**
- **合伙人**：可查看全部项目数据，但不可直接修改项目业务内容
- **FDE工程师**：只能访问所负责的项目，经合伙人授权可查看其他项目
- **自助型客户**：严格隔离，只能访问自己关联的项目，无法查看其他客户数据
- **系统管理员**：可管理系统和用户，但默认不可查看项目业务内容（需审计授权）

#### 4.3.3 自助阶段特殊安全控制
- 自助型客户无法访问完整代码生成功能和生产环境部署
- 客户上传的文档自动进行病毒扫描和敏感信息检测
- 客户操作全程记录，FDE工程师可回溯审查
- 自助项目数据与正式交付项目物理隔离
- 客户账号支持二次验证（手机验证码/邮箱验证码）

### 4.4 可扩展性要求
- 模块化架构，支持替换底层模型（DeepSeek/Qwen/OpenAI等）
- 支持插件式扩展工具与Agent
- 支持水平扩展，应对多项目并发

## 9. 风险与约束

### 9.1 技术风险
- LLM输出不可控：通过类型安全框架（Pydantic AI）+ 业务规则断言 + 人工审核兜底
- 长任务稳定性：通过任务拆解、断点续跑、超时重试机制保障
- 记忆幻觉：通过记忆来源追溯、Consolidation校验、人工确认机制控制

### 9.2 业务约束
- 客户数据安全：私有化部署、数据加密、沙箱隔离
- 客户系统对接：通过MCP标准协议适配，减少定制开发
- 交付质量底线：关键节点必须人工审核，AI输出不直接上线

### 9.3 资源约束
- MVP阶段GPU资源：1台A100（40GB）或等效算力
- 团队：2名后端开发 + 1名算法工程师 + 1名FDE业务专家
