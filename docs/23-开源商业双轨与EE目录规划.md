# 开源商业双轨与 EE 目录规划

> 版本：**v1.1（2026-09-18 重构：三档矩阵）** | 基于：v0.4.0 已发布；[10-商业计划](10-商业计划.md) Open-Core 模式
> 产物：`ee/` 目录（**2026-09-18 起本地开发、gitignore，不入开源仓库**）——本文是双轨总纲
> 一句话：**CE 保持"可独立运营的开源单机内核"，商业版沿"部署责任轴"分三档——托管（TE）→ 团队（TE）→ 企业自持平台（EE）**

---

## 1. 为什么双轨在工程上是低成本的

v0.4.0 完成两个关键动作：①**契约化外部模块**（知识库 14 号/本体 20 号）——商业版扩展走契约面不动内核；
②**参考实现即规格**——商业版替换实现有现成验收标准。ee/ 只是把这些扩展点的商业实现收拢到独立许可空间。

## 2. 产品矩阵（v1.1 重构：部署责任轴）

**TE 与 EE 的区分不是功能堆叠，而是"谁部署、谁运维、服务多大"：**

```
CE（自己装，开源单机）→ TE-Lite（我们托管：CE 云部署，免运维）
                      → TE-Pro（我们托管：多用户团队协作）
                      → EE（企业自持：独立服务器/专属云，大容量多项目平台）
```

| | **CE** | **TE-Lite** | **TE-Pro** | **EE** |
| --- | --- | --- | --- | --- |
| 形态 | 单机本地部署 | **CE 的云部署**（注册即用） | 多用户团队 SaaS | **企业级本地部署**（独立服务器/云端专属均可） |
| 部署责任 | 用户 | **我方** | 我方 | **企业自持**（交付+实施，自助维护） |
| 强调 | 开箱即用、零依赖、可审计 | 免安装免运维 | 协作/共享资产 | **大容量、多项目、企业内部自助式开发与自助维护** |
| 目标 | L0/L1 | CE 用户转化 | L2 团队 | L3 交付公司/集成商 |
| 商业 | MIT 免费 | 低价订阅 | 席位订阅 | 一口价+实施+维保 |

**转化漏斗**：CE 免费获客 → TE-Lite（付费起点：不想自己装）→ TE-Pro（团队协作）→ EE（私有化平台大客单）。

**EE 的核心场景**：交付公司买断后作为内部 AI 交付平台——几十项目并行、批量大文档、组织级知识/模板/本体资产复用（新项目从组织资产冷启动）、白标面向其客户、运维工具箱（巡检/备份/升级向导/容量告警）支撑**自助维护**不依赖驻场。

## 3. 版本规划（与 CE roadmap 咬合）

| 时间线 | CE（开源主线） | ee/（商业轨） |
| --- | --- | --- |
| v0.4.0 ✅ | 知识与本体（契约×对拍×RAG 终验） | 架构就绪（契约面成型）；ee/ 骨架建立后转本地开发 |
| v0.5 | 生态联动实测、黄金集扩展、稳定性 | **TE-Lite 上线**（CE 镜像托管化：云编排/订阅计量/自动升级——代码增量最小最快上市） |
| v0.5.x-v0.6 | 契约 P2 演进、性能验收 | **TE-Pro**（多用户/共享 KB/团队经验库） |
| v0.6+ | 模板生态、PyPI | **EE v1.0**（交付安装包/大容量层/运维工具箱/SSO/白标/审计） |

**红线 5（新增）**：TE-Lite = CE 同版本镜像，托管版功能与 CE 逐版本对齐（差异只在运维面）——杜绝"托管版悄悄多功能"侵蚀 CE 信任。

## 4. 四条工程红线（不变，全文见 ee/docs/roadmap-ee.md）

1. 单向依赖（CE 不 import ee；开源 CI 不构建 ee）
2. 契约即扩展点（不 fork 内核网关）
3. 只加不减（商业档不阉割 CE 能力）
4. 开源回馈（通用修复合回主线）

## 5. ee/ 目录与仓库策略（v1.1 修订）

- **ee/ 自 2026-09-18 起 gitignore，本地开发**——商业实现细节不出现在开源仓库（含历史）；开源侧仅保留本文（总纲级规划，无实现细节）
- 结构：`ee/src/{cloud, collaboration, multi_tenant, ops_toolkit, auth, branding}` + `deploy/` + `tests/`
- 构建：EE 镜像 = FROM core 镜像 + ee 层（私有 registry）；TE-Lite 直接编排 CE 镜像

## 6. 对社区的承诺

- CE 功能永不全量商业化；契约文档（14/20 号）永久开源——第三方可自实现替代（Open-Core 信任基础）
- 商业版通用修复 100% 回馈主线
- CE 主线坚持**单机本地部署**形态（云能力只出现在 ee/，CE 代码不含云绑定）
