# TE/EE 版本路线（roadmap-ee）

> 版本：**v0.1（骨架）** | 日期：2026-09-18 | 上游：[10-商业计划](../../docs/10-商业计划.md) / [23 号双轨规划](../../docs/23-开源商业双轨与EE目录规划.md)
> 原则：**商业版只加不减**——CE 功能全部可用（同一内核）；EE 差异 = 协作/管控/合规，不是阉割 CE。

## 功能分级总表（CE 已有 → TE/EE 增量）

| 能力域 | CE（已交付 v0.4.0） | TE v1.0（增量） | EE v1.x（增量） |
| --- | --- | --- | --- |
| 用户模型 | 单用户（单机） | **多用户 + 角色**（Owner/FDE/Viewer） | **多租户**（租户隔离/租户级配额） |
| 项目协作 | 单人全流程 | 项目成员/任务分派/评审流 | 跨租户项目共享（受限） |
| 知识库 | 契约 14 号（Embedded/kb-os） | **团队共享 KB**（kb-os 多 key 项目池） | 租户级 KB 策略（隔离/审计/合规域） |
| 经验库 | 项目记忆 + 跨项目检索 | **团队经验库**（贡献/审核/积分） | 组织级知识治理（审批流/留存策略） |
| 本体 | 契约 20 号（Embedded/独立服务） | 团队本体共享 + 合并评审 | 租户本体库 + 版本治理 |
| 品牌 | AI-FDE Engine | 去引擎品牌（中性命名） | **白标**（Logo/主题/文案/域名） |
| 认证 | 无（本地） | 邮箱密码 + 邀请制 | **SSO**（OIDC/SAML）+ RBAC 细粒度 |
| 审计 | 本地日志 | 操作日志（项目域） | **合规审计包**（全操作留痕/导出/报告） |
| 部署 | 单容器/编排 | Docker Compose（团队服务器） | **K8s 多租户 SaaS** / 私有化一键安装 |
| 商业形态 | MIT 免费 | 席位订阅 | 一口价 + 实施服务 |

## 交付顺序（依赖驱动）

```
TE v1.0（首个商业交付）
  1. 多用户 + 认证（ee/src/auth/）
  2. 项目成员与任务分派（协作最小集）
  3. 团队共享知识库（kb-os 多项目 key 池编排——复用契约 14 号，零内核改动）
  4. 团队经验库（CE 记忆层加共享域）
EE v1.0
  5. 多租户存储层（ee/src/multi_tenant/：PG 行级隔离，StorageProvider 扩展）
  6. SSO/RBAC（auth 扩展）
  7. 白标（ee/src/branding/：静态资源与文案注入）
  8. 审计合规包
  9. K8s SaaS 化部署（ee/deploy/）
```

## 工程红线（不可违背）

1. **单向依赖**：`ee/ → src/`，CE 代码永不 import ee；开源 CI（.github/workflows/ci.yml）不构建 ee
2. **契约即扩展点**：TE/EE 对知识库/本体的所有扩展必须走 14/20 号契约面（或提出契约 P2 升级），
   不得 fork 内核网关
3. **CE 不因 EE 受损**：任何 EE 特性不得移除/限制 CE 已有能力（"只加不减"）
4. **开源回馈**：EE 通用性修复（bug/性能）合回 CE 主线

## 与 CE 版本节奏的关系

- CE 按自身 roadmap 演进（v0.5+：生态联动/黄金集扩展…），EE 基于每版 CE tag 构建
- CE 大版本升级窗口 = EE 同步验证窗口（契约面稳定时 EE 升级成本≈重跑测试矩阵）
