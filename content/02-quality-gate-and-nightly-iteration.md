# 质量门禁与夜间迭代：让 AI 系统上线后不再雪崩

> AI-FDE Engine 方法论系列 · 第 2 篇 | 2026-09 | 附 10 分钟复现步骤

## 上线才是问题的开始

AI 系统有个残酷特性：**上线那天是它质量的巅峰**。

之后呢？客户改业务规则、知识库加了新文档、模型悄悄更新、用户问出训练集里没有的问题——质量持续下滑，而 FDE 已经去下一个项目了。等客户拿着 badcase 截图找上门，往往已经积累了三四十个问题。

传统应对是"收集反馈→排期→修复→重新上线"，一轮 2-4 周。问题在于：

1. **坏例散落在微信群和客服嘴里**，没人结构化收集
2. **修复没有回归保障**——改好了 A 却改坏了 B（回归事故比原问题更伤信任）
3. **人工逐条修**——而 80% 的坏例其实是同一类问题

## 两道防线：门禁 + 日迭代

### 防线一：质量门禁（Quality Gate）

任何修复要上线，先跑 Benchmark 回归，五项指标全达标才放行：

```
准确率 ≥ 80% ｜ 幻觉率 ≤ 10% ｜ 召回率 ≥ 85% ｜ 格式合规 ｜ 安全合规
────────────────────────────────────────────
任一不达标 → 自动拦截，不部署（宁可不修，不能改坏）
```

这不是新概念（CI/CD 早就这样），新的是**把它用在 AI 系统的每次内容/配置变更上**。

### 防线二：夜间迭代（Nightly Iteration）

把坏例处理变成每日流水线：

```
白天：客户/客服遇到坏例 → 10秒提交（输入/实际输出/期望输出/类型）
夜间：自动归集 → 逐条归因
        ├─ 知识缺失/Prompt格式 → 自动修复 + 知识库补充
        └─ 规则冲突/能力边界 → 生成修复建议（草稿），不是自动改
      → 回归测试 → 质量门禁 → 达标部署 / 不达标拦截
晨间：FDE 花 10 分钟看两样东西——部署报告 + 待采纳的修复建议
```

关键设计决策：**不可自动修复的问题输出"建议"而非"修复"**。业务规则冲突需要客户确认唯一口径，模型能力边界需要补充拒答话术——这些让 AI 生成草稿、人做决策，比全自动更安全也更快。

## 10 分钟复现

```bash
# 1. 启动 + 建项目（同第1篇，行业填制造业）
docker run -d --name aifde -p 8000:8000 -v aifde-data:/app/data \
  ghcr.io/cosmoxone/ai-fde-engine:latest

# 2. 提交一条"规则冲突"坏例（10秒）——这就是日常动作
curl -X POST localhost:8000/api/v1/projects/<项目ID>/badcases \
  -H "Content-Type: application/json" -d '{
    "input": "特采放行规则冲突",
    "actual_output": "可以放行",
    "expected_output": "需MRB评审",
    "error_type": "rule"
  }'

# 3. 触发夜间迭代（不带参数=自动归集所有未处理坏例）
curl -X POST localhost:8000/api/v1/projects/<项目ID>/iteration/run

# 4. 查看结果：注意 fix_suggestions——系统生成了"业务规则确认"草稿而非擅自修改
curl localhost:8000/api/v1/tasks/<任务ID>
```

第 4 步的修复建议长这样：

```json
{
  "type": "rule_confirmation",
  "action": "业务规则确认",
  "owner": "客户业务专家 + FDE",
  "draft": "检测到业务规则冲突：输入「特采放行」期望「需MRB评审」实际「可以放行」。
            建议：与业务方确认唯一口径后，更新知识库条目并在Prompt中加入明确规则"
}
```

晨间 review 的 FDE 拿着这份草稿去找客户确认口径——**10 分钟完成过去一天的沟通+文档工作**。

## 效果账

按我们实测的流程算一笔账（中型知识库项目）：

| 项 | 传统 | 门禁+日迭代 |
| --- | --- | --- |
| 坏例收集 | 微信截图，流失 70% | 结构化入库，100% |
| 单轮修复周期 | 2-4 周 | 1 天（自动类）/ 2 天（建议类） |
| 回归事故 | 每 3 轮出现 1 次 | 门禁拦截，趋零 |
| FDE 介入时间 | 每条 1-2 小时 | 每日 10 分钟 review |

## 一句话总结

> 上线后的质量不是靠人守出来的，是**门禁拦出来的 + 迭代攒出来的**。AI 修能修的，建议修不了的，人只做 10 分钟决策。
